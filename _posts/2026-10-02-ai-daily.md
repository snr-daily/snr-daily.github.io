## 模型发布

### 1. Google 发布 Gemini 4 Argon：单次输出上限 100 万 token，先只给受信任的安全防御方

Google 9 月 30 日发布新一代前沿模型 Gemini 4 Argon，由 Google DeepMind 负责人 Koray Kavukcuoglu 署名介绍。它面向长时间、多步骤的专业任务，Google 称其在软件工程、法律与金融类知识工作和网络安全防御上达到前沿水平。与以往不同，Argon 没有直接公开上线，而是先通过 Fairwind 计划提供给一批受信任的网络安全防御方，Google 表示正在参与美国政府的自愿性发布前模型访问流程，并在加固防护后再逐步放开。第三方评测机构 Artificial Analysis 已拿到模型做了测试，结论是 Google 重新回到智能水平前三的实验室之列。

- 输出长度：单次输出上限从 64K 提高到 100 万 token，Google 称模型可以在一条轨迹里生成几十万 token 来一次解决难题。据 Artificial Analysis，上下文窗口同为 100 万 token，Gemini API 新增 Long Decode Continuation 功能，长回答可以暂停后在后续调用中续写，避免请求超时。
- 价格：推介期每百万输入 token 2 美元、输出 10 美元，缓存输入按输入价打 0.5 折；推介期结束后恢复为输入 4 美元、输出 20 美元。Artificial Analysis 称折扣至少持续一个月。
- Google 自报成绩：长程软件工程基准 DeepSWE v1.1 为 77.9%；Zapier 的业务流程基准 AutomationBench 为 51.3%，排名第一；长视频理解 LVBench 为 91.7%；漏洞修复基准 CWE-bench v1 为 68%，并列第一。
- 第三方评测：Artificial Analysis 智能指数 53 分，与 GPT-6 Astra 持平，比 GPT-6.1 Sol 高 1 分；按折扣价跑完指数的单任务成本为 1.99 美元，是 Astra（3.26 美元）的约六成，但它平均每个任务输出 6.2 万 token，Astra 为 2.7 万。在 AA-Omniscience 上幻觉率 15%，Astra 为 51%。Terminal-Bench 4 得分 57%，低于 Claude Sonnet 5.5（64%）、Opus 5.5（60%）和 Astra（59%）。
- Google 内部用例：一组 Argon Agent 根据全机群的性能剖析数据自动做内存优化，上线后已释放 300 TiB 以上内存；在视频解码库 libgav1 的 Rust 移植版里重写了 3.2 万行 SIMD 代码，速度是原移植版的 2.7 倍。
- 安全与开放节奏：受信任的防御方和 Google 内部团队拿到的是不带网络安全护栏的版本；面向大众发布前，Google 要加强滥用防护、提示注入防御，并部署监控思维链和动作、必要时中止执行的机制。之后将先向付费 API 客户和 Google AI Ultra 订阅用户开放，没有给出日期。

**为什么值得关注：** 继 Anthropic 的 Mythos Preview 之后，又一家头部实验室选择先把最强模型交给防御方、再公开发布，普通开发者短期内用不上，但可以先按公布的价格和 100 万 token 输出上限评估长任务的成本。基准成绩大多是 Google 自报，第三方数据显示它在智能指数上追平而非超过 GPT-6 Astra，token 消耗也明显更多。

## 研究

### 2. 论文 Context Language Models：把上下文当成文件，让模型自己改

来自华盛顿大学、Meta 超级智能实验室等机构的 13 位作者（第一作者 Rulin Shao）9 月 29 日在 arXiv 提交论文，提出“上下文语言模型”（CLM）。普通语言模型只能把新 token 追加到上下文末尾，压缩、卸载、检索这些上下文管理工作由外部 harness 按人写的固定规则完成。CLM 的做法是把上下文镜像成一个模型可写的文件，模型既可以照常追加，也可以用 Bash 任意编辑这个文件，改动会立刻同步到下一轮的实际上下文。作者发现，不经训练、直接让现有模型这样工作，就能在多种长程任务上以更少的计算量超过现有的上下文管理方法。代码已在 GitHub 开源。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-02/2.svg" | relative_url }}" alt="CLM 怎样管理自己的上下文。上下文镜像成文件 → 模型自由编辑 → 改动同步回上下文 → 扩展到多 Agent → 服务端复用后缀缓存" loading="lazy"></figure>

- 零样本效果：用 Qwen3.6-27B 和 GPT-5.6 Sol 等现有模型，在深度研究基准 BrowseComp-Plus 上比最强基线准确率高 11.4%，同时少用 21.5% 的计算量（FLOPs）；在 TerminalBench 2.1 上与最强基线准确率持平，计算量少 29.5%。
- 长时间任务：在 12 小时的 EdgeBench（10 个任务的子集）上，比 Codex 式的摘要压缩得分高 5%、计算量少 59%；在一个 24 小时、6 个相互依赖仓库的 Agent 集群优化任务上，相同计算量下端到端加速多 65%。
- 自发行为：模型会自己定义并维护多 Agent 协作用的跟踪表，新增一种只给自己看的“内部笔记”对话角色，还会定义可复用的上下文管理函数。
- 可以学：用技能优化循环演化出一份上下文管理说明，在作者提出的诊断基准 ContextBench 的留出集上准确率最多提高 35.9 分；用在线强化学习训练 Qwen3.5-9B，BrowseComp-Plus 从 28.8% 提高到 42.5%。
- 服务端配合：模型改动上下文中间部分会让前缀缓存失效，作者提出后缀缓存复用（SCR），在效果持平的情况下比标准 SGLang 服务再少 35% 的服务端计算量。

**为什么值得关注：** 现在的编码 Agent 主要靠 harness 在固定阈值做摘要压缩，这篇论文说明把“留什么、删什么”交给模型自己决定，效果和成本都可能更好。它同时提醒推理服务方，如果上下文不再只是追加，现有的前缀缓存和按缓存计价的方式都需要调整。

## 开源项目

### 3. Cloudflare 开源决策模型 Clef 和 Clef-flash，并推出强化学习微调服务

Cloudflare 10 月 1 日发布两个自己训练的决策模型 Clef 和 Clef-flash，已上线 Workers AI，权重以 Apache 2.0 许可放在 Hugging Face 上。决策模型不生成文字，而是针对一组预设问题直接给出带概率的结构化答案（是或否、多选一、打分），适合放在 Agent 流程里做路由和判断。这类模型因 Typesafe AI 的 Jev System One 走红，Clef 的 API 与 Jev 完全兼容，可以直接替换。与 Jev 相比，Clef 带视觉编码器，能对图片内容做判断，上下文窗口为 64k（Jev 为 32k）。Cloudflare 同时推出帮客户微调 Clef 的强化学习服务，这是 Workers AI 团队第一次发布自己训练的模型。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-02/3.svg" | relative_url }}" alt="决策模型的中位请求延迟。Jev 524.1 ms；Clef 209.3 ms；DiffusionGemma Jev 84.4 ms；Kev-9B 51.4 ms；Clef-flash 38.8 ms" loading="lazy"></figure>

<details class="snr-data"><summary>查看数据</summary><table><thead><tr><th>项目</th><th>毫秒，43 项评测上的中位数，越低越好</th></tr></thead><tbody><tr><td>Jev</td><td>524.1 ms</td></tr><tr><td>Clef</td><td>209.3 ms</td></tr><tr><td>DiffusionGemma Jev</td><td>84.4 ms</td></tr><tr><td>Kev-9B</td><td>51.4 ms</td></tr><tr><td>Clef-flash</td><td>38.8 ms</td></tr></tbody></table></details>

- 规格：Clef 以冻结的 Qwen3.8-27B 为骨干，Clef-flash 以 Qwen3.5-9B 为骨干，各自训练一个路由打分头和秩为 256 的 LoRA 适配器。推理时骨干只做一次预填充，再并行给所有合法选项打分，不逐 token 生成文字。
- 质量：在 Cloudflare 自己跑的 Jev Decision Index 评测里，Clef 在 BANKING77 意图分类上宏平均 F1 为 94.20（Jev 为 79.74），API-Bank 准确率 91.93（Jev 为 88.19）。但并非全面领先，When2Call 上 Jev 为 80.97，高于 Clef 的 72.37；在 Typesafe 自己的四类工作流评测里，Clef 赢了三类，Agent 轨迹观测一类落后。
- 延迟：在 43 项评测上，Clef 中位延迟 209.3 毫秒，Clef-flash 为 38.8 毫秒，Jev 为 524.1 毫秒。
- 内部用例：Cloudflare 威胁情报团队用 Clef 配合 Browser Run 给网站域名分类，抓取、渲染加分类共 2.2 秒；同样流程用通用模型 gpt-oss-120b 需要 4.7 秒，而且只返回两个分类。
- 训练方法：用带标签平滑的交叉熵加 Brier 损失校准概率，数据是内部合成的、打乱字段顺序和 schema 结构的样本；另外提出 RLCD 作为第二优化目标，对相邻的序数选项给部分分数。
- 微调服务：先由 Cloudflare 的前线工程师团队手把手做，之后再做成自助平台。流程是用 AI Gateway 采集请求数据，Workers AI 生成 rollout，Containers 作为强化学习沙箱打分，新的 Trainer 更新权重，最后把模型重新部署到 Workers AI。Cloudflare 承诺不读取、不保存、不用请求数据训练，使用微调服务的除外。

**为什么值得关注：** 决策模型这个品类一个月内已经有了多个实现，Clef 由大型云厂商托管，同时开放权重并兼容 Jev 接口，想把分类和路由从大模型里拆出来的团队多了一个可自托管的选择。评测是 Cloudflare 自己跑的，而且各项互有胜负，替换前应在自己的数据上对比。

### 4. Ai2 发布 Olmo-core 3：开源的大规模 MoE 训练框架，已测到万亿参数

艾伦人工智能研究所（Ai2）10 月 1 日发布 Olmo-core 3，这是其语言模型训练框架的一次大升级，重点是重新设计的混合专家（MoE）训练系统，代码和技术报告全部公开。MoE 模型每个 token 只激活少数专家，理论上可以用较少计算换来更大的参数量，但整个模型仍要放进 GPU 内存并更新，把数据路由到分布在集群各处的专家也有通信开销，模型越大，这些开销越容易吃掉省下的计算量。Olmo-core 3 把旧版基于 FSDP、每个小批次都要重新汇集权重的做法，换成基于 DDP、让专家常驻 GPU 并把数据送过去的方案。Ai2 表示下一代 Olmo 模型将采用 MoE 架构，就在这套框架上训练。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-02/4.svg" | relative_url }}" alt="训练 470 亿参数 MoE 的单 GPU 吞吐。Olmo-core 3（基于 DDP） 52,000；旧版实现（基于 FSDP） 19,400" loading="lazy"></figure>

<details class="snr-data"><summary>查看数据</summary><table><thead><tr><th>项目</th><th>每块 GPU 每秒处理的 token 数，8 块 NVIDIA B300，越高越好</th></tr></thead><tbody><tr><td>Olmo-core 3（基于 DDP）</td><td>52,000</td></tr><tr><td>旧版实现（基于 FSDP）</td><td>19,400</td></tr></tbody></table></details>

- 扩展性：一项基准里，专家数从 8 个增加到 128 个，每个 token 仍只选 4 个专家，激活参数保持在约 32 亿；总参数量从 46 亿增长到 470 亿，训练吞吐下降不到 5%。
- 与旧版对比：在 8 块 NVIDIA B300 上训练 470 亿参数的 MoE，新框架每块 GPU 每秒处理 5.2 万个 token，旧实现为 1.94 万个，约 2.7 倍。
- 万亿规模：在 512 块 B300 上测试了总参数 1.2 万亿、每 token 激活 583.6 亿参数的配置；配合 DeepEP v2 做过 2.38 万亿参数的短时容量测试。这些测试用随机路由衡量系统性能，不代表训练出的模型质量。
- 关键技术：专家并行、流水线并行和分布式优化器负责把模型和训练状态分散到各 GPU；路由元数据留在 GPU 上，再用分组 GEMM 把许多小的专家计算合并执行。
- 低精度格式：支持 MXFP8，在 4 块 B300 上的对照测试里，训练吞吐比 BF16 高约 21%，峰值内存从 103 GiB 降到 95 GiB。
- 负面结果也写进了报告：例如一个用来鼓励均衡路由的指标在实际负载更不均衡时反而变好，作者称之为“token 选区划分”；让通信和计算在不同 GPU 流上重叠，有时反而更慢。

**为什么值得关注：** 公开的大规模 MoE 训练方案此前主要是 NVIDIA 的 Megatron-Core，Olmo-core 3 给学术界和小团队多了一个完整开源、带实测数据和失败经验的选择。它目前只证明了系统吞吐，用它训练出的模型质量还要等下一代 Olmo。

来源：[Ai2 博客（Hugging Face）](https://huggingface.co/blog/allenai/olmocore3) · [OLMo-core GitHub 仓库](https://github.com/allenai/OLMo-core)

### 5. Magnitude：在本机现场编译调优内核的开源推理引擎，面向本地 Agent

YC S25 团队 Magnitude 9 月 30 日在 Hacker News 正式发布同名开源推理引擎，专门用来在个人电脑上给 Agent 跑开放权重模型。作者认为现有引擎各有取舍，vLLM、SGLang 为数据中心的批量推理设计，llama.cpp、Ollama 追求广泛兼容而没有针对具体硬件优化。Magnitude 的做法是把计算内核写成带可调参数的形式，在模型运行前先在用户的实际设备上编译和调优，并只为最流行的几类开放权重模型手写优化内核。它用 Rust 编写，以桌面应用形式发布，支持 Apple Silicon、NVIDIA、AMD 显卡和纯 CPU。

- 自测成绩（对比 llama.cpp，Qwen 3.6 35B A3B 4 bit 量化，64k 上下文）：M4 Pro 48 GB 的 Mac 上解码从每秒 30 个 token 提高到 57 个，快 92%；DGX Spark 上从 49 提高到 58，快 19%，预填充快 23%。
- 内存：启动时只预留模型权重所需的内存，会话变长时动态增加、Agent 停止后释放；每个 Agent 的内存占用比 llama.cpp 少 27% 到 28%。
- 并发：借鉴 SGLang 的做法让多个会话共享前缀缓存，同时按内存相邻性安排存放位置，避免单会话性能下降。
- 接入：一键连接 Pi、OpenCode、Hermes、Codex、Claude Code、Cline 等 Agent，其他工具可以走兼容 OpenAI 的 API；模型在 Agent 需要时自动启动，闲置后关闭。
- 许可与平台：Apache 2.0，支持 macOS、Windows 和 Linux，GitHub 仓库目前约 6200 星。

**为什么值得关注：** 在本机跑编码 Agent 的人越来越多，这类负载的特点是会话长、多个会话并行，电脑还要同时干别的事，和聊天场景不同。成绩都是作者自测，而且只覆盖一个模型和两台机器，值得在自己的硬件上和 llama.cpp 实际对比。

来源：[GitHub 仓库](https://github.com/magnitudedev/magnitude) · [Launch HN 发布帖](https://news.ycombinator.com/item?id=49911995)

### 6. DeepSeek Harness 桌面版开放下载：支持 macOS 和 Windows，一切皆插件

DeepSeek 在官网上线了开源 Agent 框架 DeepSeek Harness 的桌面版下载，支持 macOS 和 Windows，官网称它已面向全球公开预览，10 月 2 日登上 Hacker News 首页。DeepSeek Harness（命令名 dsh）建立在名为 Cordis 的元框架上，核心理念是“一切皆插件”：Agent 循环、子 Agent、终端等能力都以插件形式存在，可以替换或扩展。它不只面向编程，也覆盖整理文件、分析数据、写文档和做幻灯片等日常工作，定位上对应 Claude Code、Codex 这类工具的桌面应用。

- 插件：官方插件包括 Agent 循环、子 Agent、终端，以及标为实验性的 Agent 团队、自动审批审查、定时任务和语音输入。用户可以在“创作者模式”里通过对话让它现场写出并安装一个新插件。
- 上手：除了下载桌面版，装好 Node.js 后运行 npx @deepseek-ai/dsh web 即可启动网页界面；也可以克隆仓库从源码构建。
- 开源情况：仓库 deepseek-ai/deepseek-harness 以 MIT 许可开源，目前约 24.2 万星。README 仍把项目标为开发者预览，并提示会有不兼容的改动。
- 最近更新：9 月 29 日的 dsh-v0.2.0-rc.2 让 macOS 和 Windows 桌面端自带 dsh 命令，管理插件不再需要另装 Node 或 pnpm。
- 实现与计费：据 36 氪转载的 AI 前线 9 月 25 日报道，桌面端基于 Electron，复用已有的网页界面和 Agent 运行逻辑；当时的预览版需要账户有余额或填入自己的 API Key 才能使用。
- 调试：内置开发者工具，可以查看每一轮的系统提示、工具调用参数、返回结果和耗时。

**为什么值得关注：** DeepSeek 把自家 Agent 框架完整开源并做成了桌面应用，插件化架构让开发者可以替换其中任何一层，而不是只能接受官方的整套设计。项目还在快速变动，接口不稳定，生产环境使用前要留意版本。

### 7. OpenAI 披露打掉一场套取推理过程的蒸馏行动，称核心账号与月之暗面有关

OpenAI 9 月 30 日发文称，它识别并阻断了一场有组织的蒸馏行动，对方的目标是大规模套取模型受保护的推理过程。OpenAI 把其中的核心账号群归到与中国公司月之暗面（Moonshot AI，Kimi 的开发方）有关联的个人身上，但据 The Hacker News，它没有公布支持这一判断的技术证据。按 OpenAI 的说法，对方没有破解加密、入侵数据库或拿到别人的对话，而是通过操纵与模型的交互，让本应隐藏的推理内容以请求方看得见的形式被复述出来。OpenAI 说已封禁相关账号，并补上了相关漏洞。

- 规模：进一步调查后，OpenAI 在 1.5 万多个用户身上发现了相关的提示模式。SC Media 转述称，OpenAI 表示不确定所有操作者是否都与同一家竞争对手有关。
- 修补措施：封禁欺诈账号；关闭了一条通路，此前已经持有他人加密推理内容的人可以把它重放并还原出明文；新增检查，发现流式输出可能暴露推理内容时先行拦截。

### 8. OpenAI 与 Synopsys 合作开发芯片设计专用模型 GPT-Synopsys

EDA 厂商 Synopsys 和 OpenAI 9 月 30 日宣布签署多年期合作协议，共同开发名为 GPT-Synopsys 的专用模型，让它直接操作 Synopsys 的芯片设计工具来完成设计流程。Synopsys 的说法是，现在的做法是把通用模型接到 EDA 工具上跑流程，下一步是让前沿模型本身成为这些工具的“原生专家用户”，会像资深工程师那样运行工具、解读输出并反复优化设计。为此 OpenAI 将获得 Synopsys EDA 工具的授权，用于开发这个模型。新闻稿没有给出发布时间、基准数据或价格。

- 部署：GPT-Synopsys 运行在 OpenAI 托管的基础设施上，设计上可以与客户自己的 Agent harness 互通，并与 Synopsys.ai 和 Synopsys Autopilot Agent 平台深度集成。
