## 研究

### 1. Beetle 公布 330 个单语与双语模型及检查点，用于追踪第二语言学习

剑桥大学、EleutherAI 与牛津大学研究者介绍 Beetle，用可控预训练研究模型如何学习第二语言。作者 10 月 24 日的介绍指向 285 个双语、45 个单语开放模型及大量训练检查点，覆盖不同语言与暴露课程。项目将分词器、目标语言、训练预算和语言接触顺序分别控制，便于研究能力何时出现。它的重点是学习过程与人类语言行为，不是发布一个新的通用聊天模型。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-26/1.svg" | relative_url }}" alt="Beetle 如何研究语言学习过程。固定实验的其他条件 → 改变双语暴露课程 → 对照检查点与人类数据" loading="lazy"></figure>

- 项目覆盖 21 种第一语言与 B1–B5 五种课程；课程改变第二语言何时进入训练，以及两种语言数据随训练阶段的比例。
- 三档数据预算为 100M、2B、24B token，即 1 亿、20 亿、240 亿训练 token；这些数字不是模型参数量，也不是上下文长度。
- 评估包括第二语言阅读时间预测、语法判断和跨语言结构启动；作者报告分阶段课程比平衡双语训练更贴近语言学习者的阅读时间，小数据规模及类型接近的语言对更明显。
- 对照需保持其他变量固定，不能将某一人类行为拟合结果直接改写成所有多语言 NLP 任务的全面提升。
- 作者提供项目页、论文、模型与训练框架入口；本期阅读了介绍、项目页和 ACL 论文摘要，未下载全套模型、训练或复跑人类行为拟合。

**为什么值得关注：** 多语模型研究可据此比较训练中间状态，而非只对最终分数作解释。复用时先匹配第一语言、课程与 token 预算，再决定检验哪项机制。

### 2. Lynch Lab 的 200 例皮损评测：CNN 分类更准，但默认阈值漏放更多需处置病灶

Lynch Lab 近期公开的对照把 200 例经病理确认的皮损交给 GPT-6 Astra、Claude Fable 5.1 与微调 Inception v3。六分类首选诊断中，CNN 对 125 例，两款 LLM 分别对 84、85 例。与此同时，在 100 例不应直接放行的病灶里，CNN 默认阈值只保留 77 例，LLM 分别保留 97、96 例。分类准确率与是否放行是两个目标，不能把前一项胜出写成临床筛查全面胜出。

- 测试包括 100 例需继续处置病灶与 100 例可放行的良性病灶；需处置组含 30 例黑色素瘤，也包含其他癌症与光化性角化病，不能统称 100 例都是癌症。
- 两款 LLM 都得到临床近照与皮肤镜图，使用相同提示和默认设置，每例仅运行一次。CNN 对两幅图打分并组合，皮肤镜权重较高，比较的是不同训练与使用方案。
- CNN 在单张 H100 上用 68011 幅公开图像微调，测试病灶及同患者其他图像从训练和验证中排除；作者无法确认公开数据是否进入 LLM 训练。
- 默认阈值下，CNN 将 30 例黑色素瘤中的 18 例放行，两款 LLM 分别放行 3、4 例。把 CNN 阈值调到匹配高保留率时可减至 2 或 1 例，但不能沿用原阈值下的全部指标。
- 这是作者的小样本对照，不是临床部署验证；全部病例都做过活检，样本比普通人群疑难，单次 LLM 回答和 30 例黑色素瘤也带来较大不确定性。
- 作者公开病例、提示、回复与评分代码入口，并披露分析和初稿用了 Claude Code；本期只读方法与结果，没有使用患者原图、运行诊断或复跑模型。

**为什么值得关注：** 技术评测应同时报告分类、阈值和漏放代价，并明确训练数据与输入方式。这个结果能提示通用模型和专用模型的取舍，不能据此选择个人诊疗方案。

来源：[Lynch Lab：完整测试方法、结果表与限制](https://lynchlab.net/llm-skin-cancer)

## 开源项目

### 3. llama.cpp b11871 拒绝超过 128 层的 JSON，避免递归遍历导致服务崩溃

llama.cpp 10 月 25 日的 b11871 预发布构建加入 JSON 深度预检。此前部分请求内容会进入 schema、Jinja 与决策代码的递归遍历，极深嵌套可能耗尽 HTTP 线程栈并使 llama-server 退出。新行为在相关入口遍历前检查深度，超过 128 层返回 HTTP 400。此次属于输入加固，不是模型速度或精度更新。

- 覆盖 common_chat_templates_apply 中的 tools、工具调用参数、chat_template_kwargs 与 json_schema，也覆盖 /completion 的 json_schema 和完整 /v1/systemone 请求体。
- 官方说明的崩溃表现包括 macOS SIGBUS 与 Linux SIGSEGV；嵌套深度及平台影响依赖具体环境，本文不提供攻击载荷，也未测试线上服务。
- 过深的 Gemma 4 工具结果按文本保留；不能把这条规则简化成所有 HTTP JSON 超过同一深度都按同一路径处理。
- 该页面标记 Pre-release。采用者需核对实际打包版本是否包含修复，并测试正常工具 schema、输出格式与错误处理；本期未替换本机运行时。

**为什么值得关注：** 将请求结构限制放在递归处理前，可减少不可信输入造成的可用性问题。服务端更新之外，调用方也应能识别 400 并反馈结构错误。

### 4. Qwen Code 0.26.1 加入模型外定时检查：无变化时可跳过模型回合

Qwen Code 0.26.1 于 10 月 24 日发布，汇入定时任务 gate、托管会话恢复与多项权限和输入处理改动。gate 是调度器在提示词交给模型前运行的 shell 检查，命令成功且无输出时跳过本次模型回合；有输出才投递任务与结果。它可减少没有变化的轮询对话，但进程检查本身仍消耗资源。该版本也包含 QQ 群会话隔离的破坏性修正，升级不宜只看新增功能。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-26/4.svg" | relative_url }}" alt="Qwen 定时任务 gate 的基本行为。调度器先运行检查 → 按输出和退出状态分流 → 必要时才投递模型" loading="lazy"></figure>

- 底层 gate 设计对失败、无法启动或超过 60 秒的检查按连续失败段报告，后续静默计数直到恢复；检查结果是数据，不应被当作更高权限指令。
- 无人值守 shell 命令在提出时确认、运行时再次检查权限；仅有旧 cron_create 允许规则不足以单独授权 gate。各集成仍需按自身接入路径配置。
- 发布说明另列 Managed 自动化的运行时探针、PR watch 探针和 WebShell 支持；不能把底层调度 gate 的所有语义不加区分套到每种托管自动化。
- 托管工作区恢复会等待持久化状态稳定，并在 WebShell 显示原因与可用动作；手动压缩仅在空闲时进行，保留审计历史。
- daemon token 可选择保存为仅所有者可读的文件，停止 daemon 时删除；并非默认明文持久化所有凭据。QQ bot 在 thread 范围下恢复按群隔离，官方列为 Breaking Changes。
- 发布说明还修复不完整 ACP 编辑参数、超时 review 子进程树回收等问题；本期仅核对 release 与 gate 原始 PR，未升级本机客户端或修改现有定时任务。

**为什么值得关注：** 持续监测可先由确定性检查判断是否值得唤醒模型。采用时要分别验收安静跳过、连续失败、权限拒绝与会话恢复，避免把后台健康等同任务完成。

来源：[Qwen Code：v0.26.1 完整发布说明](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.1) · [Qwen Code：模型外调度 gate 的设计与行为](https://github.com/QwenLM/qwen-code/pull/15069)

### 5. AtMem 2.3.10 增加只读证据检索：按来源核验权限，默认仍需显式启用

AtMem 作者 10 月 24 日介绍 2.3.10，在既有确定性记忆注入之外增加独立、只读的证据探索会话。检索通道先提名证据身份，再从规范存储重新读取内容并检查权限、范围与生命周期，读者可继续查看原文片段。安装新版不会自动开启远程分类器、下载嵌入模型或为所有 Agent 启用探索。返回的原文提供推理依据，本身不授予写入记忆或执行外部操作的权限。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-26/5.svg" | relative_url }}" alt="AtMem 只读探索如何交付证据。检索通道提名证据身份 → 规范存储重新核验 → 返回有预算的原文片段" loading="lazy"></figure>

- 对模型暴露 memory_search 和 memory_inspect；租户、数据库、授权回调与预算由宿主管理，模型不能用这两个只读操作切换租户或写入。
- 默认 Hermes 探索租约最多 8 次操作、累计 96000 响应字节、单次 16000 字节、15 分钟有效期；这是租约上限，不是每个测试任务实际耗时或用量。
- 作者报告 2.3.10b1 在 600 个 DolphinBench 任务中通过 390 个、65.0%；需任务所有检查通过才计成功，失败和超时未从分母删除。
- 该测试为 Hermes 加 GPT-5.6 Luna 的整套配置，任务时延中位数为 85.78 秒，包含模型和工具开销，不能写成记忆搜索延迟。
- 没有匹配的 2.3.9 对照或完整组件消融，其他系统仅引用既有结果；开发用过公开任务子集，不能据此建立受控排名或归因某个模块的收益。
- 稳定版从 beta 晋级，并非另跑一轮 600 任务。来源摘要只绑定某份表示，不证明语句为真；原文还留有聚合复算脚本调用待补项，本期不声称已完成一键复现。

**为什么值得关注：** 可取之处是把检索相关性、材料是否仍适用及证据是否充分分开处理。生产接入仍依赖规范存储、宿主授权和缓存清理，单次自测不能替代对抗与生命周期验证。
