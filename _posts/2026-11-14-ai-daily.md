Edge0 发布面向笔记本的 145B 模型，Zyphra 开放可在端侧运行的语音合成模型。llama.cpp 与 ggml 的库版本进入 1.0，Diffusers 新增五套模块化流程，Ai2 发布了评估模型能否理解用户真实目标的 XYBench。

## 模型发布

### 1. Edge0 发布 145B 本地模型，厂商报告笔记本解码超过 80 token/s

Edge0 发布 Edge0-145B，并公开权重与配套推理框架。模型让部分专家共享大矩阵，运行时在 GPU、系统内存和 SSD 之间调度权重。厂商在笔记本测试中报告预填充超过 1,100 token/s、解码超过 80 token/s。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-14/1.svg" | relative_url }}" alt="Edge0-145B 如何在笔记本上调度专家。专家共享大矩阵 → 按层调度权重 → CPU 与 GPU 并行" loading="lazy"></figure>

- 发布页的性能表列出 29 GB 峰值内存，页面另一处对比给出 28 GB。两处数字分别保留原有口径，不能用来确定最低整机内存。
- 框架将常用专家留在 GPU 内存，CPU 并行处理其余部分，推测解码可在一次验证中处理多个候选 token。
- 同期提供 Edge0-120B 权重与可离线使用核心功能的 Edge0 App。

**为什么值得关注：** 验收本地部署时，可把冷启动、长输入预填充、稳定解码和各层内存占用分开测，再判断当前设备能否满足任务需求。

来源：[Edge0 发布公告与内部测试](https://edge0.ai/blog/introducing-edge0-145b-frontier-ai-capabilities-on-your-own-computer)

### 2. Zyphra 开放 ZONOS3-Mini，可在端侧合成 43 种语言的语音

Zyphra 发布 ZONOS3-Mini，面向多语言语音合成和语音表现控制。模型共有 8 亿参数，每次激活约 1 亿，采用每秒 15 帧的音频编解码器。官方提供浏览器 WebGPU 和 Apple Silicon MLX 等运行方式。

- 模型权重采用 Apache 2.0，运行时代码采用 MIT。支持语言包含普通话、日语和韩语。
- 团队报告 Pixel 9 浏览器首段音频延迟低于 570 毫秒，M3 MacBook Air 低于 150 毫秒。
- 在单张 H100 80 GB、并发 8 的测试中，首段音频延迟中位数为 80 毫秒。不同硬件和测试配置的数字不做同条件排名。

**为什么值得关注：** 可以用目标设备测首次发声、持续生成和长文本稳定性。语音输出的响应时间还会受上游模型和播放缓冲影响。

来源：[Zyphra 发布与评估说明](https://huggingface.co/blog/Zyphra/zonos3-mini) · [模型权重与运行资料](https://huggingface.co/Zyphra/ZONOS3-Mini)

## 研究

### 3. Ai2 发布 XYBench，测试模型能否解决用户真正想解决的问题

Ai2 与合作团队发布 8,115 道题的 XYBench，区分用户明说的请求与上下文指向的目标。团队以单轮回答测试五款模型，分别评估答案是否包含解决方案、把重点放在哪里，以及是否识别错误前提。在 Stack Overflow 子集中，模型主要聚焦真实目标的回答占 35% 至 41%。

- 数据含 1,557 道 Stack Overflow 题、184 道 Stack Exchange 题、102 道人工整理题，以及 6,272 道根据 WikiHow 指南生成的题。
- 在 Stack Overflow 子集，五款模型有 59% 至 71% 的回答提及真实目标的解法。提及与作为答案重点分别计量。
- 测试采用自动评审，两名人工评审抽查 500 条模型回答。研究覆盖英语，题目以操作性问题为主。

**为什么值得关注：** 为技术支持助手做回归评测时，可以把识别根因、提出解决方案和答案重点设为独立指标。

来源：[Ai2 发布与评估口径](https://huggingface.co/blog/allenai/xybench)

## 开源项目

### 4. llama.cpp 和 ggml 的库发布 1.0，公开接口破坏性变更将升级主版本

ggml-org 发布 libllama 和 libggml 1.0.0。两者采用语义化版本管理公开库接口，并将不兼容的 API 或 ABI 变更体现在主版本中。项目把库头文件目录列为公开接口范围，便于下游判断升级影响。

- libllama 的公开头文件位于 llama.cpp 的 include 目录，libggml 的公开头文件位于 ggml/include。
- 兼容的功能、后端、模型和 API 新增归入次版本，API 无变化的缺陷修复归入补丁版本。
- 公告列出预发布构件、Docker、Homebrew、conda-forge 和移动端构件等分发渠道。

**为什么值得关注：** 直接链接这两个库的应用可以按主版本约束依赖，并为公开头文件与二进制链接保留升级检查。

来源：[ggml-org 的 1.0 公告和版本规则](https://huggingface.co/blog/ggml-org/llama-cpp-v1)

## 开发工具

### 5. Diffusers 0.43.0 新增五套生成流程，接入带声视频与语音驱动动画

Hugging Face 发布 Diffusers 0.43.0，将五个模型接入模块化生成流程。Pika H3 Flex 能同时生成视频和同步立体声，Kandinsky S2V 则按参考图与现有语音生成动画。更新也加入 MiniMax-H3-Image、P-H3-Image 和 PAN 2 模拟器。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-14/5.svg" | relative_url }}" alt="Kandinsky S2V 如何用录音驱动动画。提供参考图和录音 → 每段生成五秒画面 → 将记忆传给下一段" loading="lazy"></figure>

- Pika H3 Flex 采用六步采样，支持文字、首尾帧和多模态参考输入，并支持加载 LoRA。
- Kandinsky S2V 以五秒为一段生成视频，在段间传递 FramePack 记忆。输入录音作为成片音轨。
- P-H3-Image 支持最多八张输入图片。PAN 2 集成的是 29B 生成模拟器，提示词推理模型另见文档。

**为什么值得关注：** 接入时先按素材选择流程。如果音频已录制，可以测试跨段动作连续性。如果需要模型生成配套声音，可以测声画同步。

来源：[Diffusers 0.43.0 发行说明](https://github.com/huggingface/diffusers/releases/tag/v0.43.0)
