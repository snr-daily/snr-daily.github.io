## 模型发布

### 1. Meta 开放 Muse Spark Open 权重：816B 总参数、42B 激活，支持四类输入

Meta 10 月 15 日开放 Muse Spark Open，面向编码和多步 Agent 工作。模型接收文本、图像、音频与视频，输出文本，上下文最高约 100 万 token。它采用稀疏专家架构，总参数约 816B，每个 token 激活约 42B。激活规模降低单步计算量，但全部专家仍需存储，不能按 42B 模型估算部署内存。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-16/1.svg" | relative_url }}" alt="Muse Spark Open 的输入、计算与输出。多模态输入 → 稀疏专家计算 → 文本输出与工具调用" loading="lazy"></figure>

- 模型每个 MoE 层有 256 个专家，每个 token 选择 8 个；提供 BF16 与 NVFP4 检查点。
- Hugging Face 集成说明称 BF16 权重文件约 1.5 TB；NVFP4 面向 Blackwell。长上下文的 KV 缓存还会增加内存需求。
- Transformers、llama.cpp、vLLM 与 SGLang 均有集成说明；不同后端和量化格式的部署条件需要分别核对。
- 权重采用 Muse Model License，附使用与标识等条件；开放权重不应写成无条件的通用开源许可。

**为什么值得关注：** 自托管评估应同时记录权重、KV 缓存、并发和量化误差。多模态输入与工具调用拓宽了任务范围，但不能仅凭激活参数量判断硬件门槛。

来源：[Hugging Face 集成与部署说明](https://huggingface.co/blog/meta-muse-spark-open) · [Meta 官方模型卡与许可](https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B)

### 2. FLUX.3 Image Klein 接入 Diffusers：支持多参考图与边界框布局控制

Black Forest Labs 的 FLUX.3 Image Klein 已在 10 月 15 日获得 Diffusers 集成。模型统一处理文生图、多参考图编辑和提示词中的边界框布局控制，蒸馏版默认 16 步，基础版默认 50 步。官方模型卡称图像 Transformer 为 5.6B 参数，文本编码器另计。HF 在单张 H100 上测得 1024×1024 文生图约 1.93 秒，但这不包括任意硬件或全部前置流程。

- 单张 H100 80GB、无卸载、预热后三次平均：1024×1024 文生图 1.93 秒，同尺寸单参考图编辑 3.87 秒。
- 布局框使用 0–1000 归一化坐标，顺序为上、左、下、右；编辑可指定参考图来源位置与目标位置，框不是像素级硬遮罩。
- 蒸馏检查点用于生成和编辑，基础检查点用于微调与 LoRA；另有 FP8 与 NVFP4 权重格式，文件体积不等于完整运行显存。
- 模型要求完整场景描述。参考代码默认使用提示词扩写器，Diffusers 不会自动运行该扩写步骤；模型采用自定义 FLUX Kommunity License。

**为什么值得关注：** 做可控编辑时，应分别检查构图、参考图一致性与局部修改范围。性能复测还需计入文本编码、扩写、参考图数量和显存配置。

来源：[HF Diffusers 集成与测试](https://huggingface.co/blog/flux-3) · [BFL 官方模型卡](https://huggingface.co/black-forest-labs/flux-3-image-klein)

### 3. IBM 发布 Granite Switch 4.1：一个端点切换聊天、决策与英语转写

IBM 10 月 15 日介绍 Granite Switch 4.1 的 8B 与 30B 配置，把基础模型、决策适配器、安全适配器和语音转写组件组合到同一服务端点。Activated LoRA 允许后续适配器决策复用基础模型生成的 KV 缓存。语音侧先由独立嵌入组件转写，再把文字接入聊天上下文。它统一了服务入口，但语音编码器与 LLM 尚未联合训练。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-16/3.svg" | relative_url }}" alt="Granite Switch 的音频输入路径。英语音频 → 文字进入上下文 → 聊天或适配器决策" loading="lazy"></figure>

- 8B 模型卡标注基础模型 128K 上下文，包含 decision 与 guardian-core 两个按需激活的 aLoRA；许可为 Apache 2.0。
- 内置 Granite Speech 5.0 TurboCTC 为 470M 参数英语转写模型，输出小写且无标点，暂不支持解码时引导。
- IBM 称组合模型显存接近单独基础模型；公告未给出可直接外推到所有负载的端到端成本数字。
- 用户可从 Granite Libraries 组合适配器；Mellea 适配器训练 SDK 仍属后续计划。模型卡日期为 10 月 14 日，介绍文章发表于 15 日。

**为什么值得关注：** 共享端点和缓存可能减少重复预填充与模型切换成本，但需要按聊天、决策和语音分别验收质量。多能力组合不等于原生联合训练，也不自动覆盖中文语音。

来源：[IBM Granite Switch 4.1 公告](https://huggingface.co/blog/ibm-granite/granite-switch-4-1) · [8B 模型卡与语音限制](https://huggingface.co/ibm-granite/granite-switch-4.1-8b)

## 开源项目

### 4. Perplexity 公开 SPACE 沙箱平台：通过 HTTP API 管理隔离微虚拟机

Perplexity 的 SPACE 仓库现已公开，采用 Apache 2.0 许可证，面向 Agent 和用户代码执行。平台以 Firecracker 微虚拟机提供 Linux 环境，通过 HTTP API 创建沙箱、执行命令、收集输出和管理生命周期。模板定义初始环境，同一沙箱可保留可写文件系统并运行多条命令。本条依据可读仓库核实功能，不引用无法复核的安全零失效率或性能宣传数字。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-16/4.svg" | relative_url }}" alt="SPACE 的基本执行流程。按模板创建沙箱 → 创建会话并附着 → 管理生命周期" loading="lazy"></figure>

- 生命周期操作为异步：API 返回 operation ID，调用方查询完成状态。
- 命令输出使用独立数据平面连接与会话级附着令牌；创建命令会话与附着启动进程是不同阶段。
- 仓库提供本地 Kind 集群安装、首个沙箱、暂停与挂起、兼容封装和排障文档。
- 应用负责选择运行内容与保留结果，SPACE 管理沙箱及进程；本期未安装平台或执行安全测试。

**为什么值得关注：** 执行隔离与任务编排可以分层管理，便于对生命周期和命令结果做明确验收。采用前仍需验证网络出口、凭据隔离及故障恢复是否符合自己的部署要求。

来源：[Perplexity SPACE 官方仓库](https://github.com/perplexityai/SPACE)

### 5. Hugging Face 提出 BERT 分词优化：相对 0.23 最高约 50 倍，仍在 PR 阶段

Hugging Face 10 月 15 日介绍 Tokenizers 的 BERT 归一化优化，重点是跳过不必处理的字符，而非改变模型分词结果。作者称结合此前库级改进，bert-base-uncased 相对 0.23 最高约快 50 倍；本轮分支相对主线最多再快约 5.7 倍。改动在文章发表时仍处于 Pull Request 阶段。收益明显依赖文本组成，中文与极短输入可能没有收益甚至变慢。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-16/5.svg" | relative_url }}" alt="BERT 分词优化主要作用在哪里。输入文本 → 归一化快路径 → WordPiece 与 token ID" loading="lazy"></figure>

- 优化包括 SIMD 查找 ASCII 区间、按 Unicode 字符页缓存归一化判断，以及仅在实际变化时分配输出内存。
- 基准使用英语、俄语、希腊语、阿拉伯语、中文和代码语料，比较主线、优化分支与 0.23.2，逐次核对输出 token ID 哈希一致。
- 测试使用两台 AMD EPYC 7R13 和一台 Intel Xeon Platinum 8488C，单线程固定核心，预热后交替测试，报告各轮比值中位数。
- 作者指出中文整体几乎不提速；保留大小写的 BERT 在 64 字节及以上中文输入上慢约 8%–15%，极小输入也可能因新增处理开销退步。

**为什么值得关注：** 嵌入、重排和分类服务应先用实际语言与输入长度测量预处理瓶颈。PR 提案中的最高倍数不应写成已发布稳定版对所有文本的提升。

来源：[HF 作者方法、基准与局限](https://huggingface.co/blog/huggingface/tokenmaxxing-bert)

### 6. OpenAI 推出 Rosalind 学术计划：美国高校实验室可申请最多 30 个免费席位

OpenAI 10 月 15 日宣布 Rosalind Academic Plan，为符合条件的美国高校实验室提供 GPT-Rosalind 研究入口。计划最多资助 30 个 Business Standard 席位、期限最长 12 个月，GPT-Rosalind 的启用须通过可信访问审核。它面向生命科学研究与工具工作台，不是向所有用户免费开放模型。当前计划不含 API 访问。

- 由 PI 或实验室负责人代表团队申请；已有 OpenAI Enterprise 协议的大学须通过其现有机构访问流程。
- 获批后由负责人管理最多 30 名指定成员的权限，并承担获准用途的管理责任。
- 公告称计划中共享的研究数据默认不用于训练模型；可用模型仍受计划用量限制。
- 本次是研究访问计划变化，公告展示的工作流案例不构成对科学结论正确性或实验可行性的验证。

**为什么值得关注：** 需要区分机构与成员资格、研究工作台权限及 API 权限。研究者仍需对证据、预测值和实验结果作独立核验。

来源：[OpenAI 计划公告与资格范围](https://openai.com/index/introducing-the-rosalind-academic-plan/)

### 7. Anthropic 让 6 名 METR 评估员入驻：提供内部访问，并保留独立发表权

Anthropic 10 月 15 日宣布，已为 METR 的六人团队提供公司硬件、办公空间，以及接近内部风险评估团队的工具和系统访问。安排允许评估员理解训练、安全措施和事件处置，而不只测试一个模型接口。METR 可独立发表风险分析，Anthropic 不能否决发布，但可要求删去预先限定类别的信息。客户数据、法律特权信息及部分架构信息仍有边界。

- METR 入驻团队与其其他项目人员隔离，按协议和 Anthropic 的安全标准工作。
- METR 可公开说明删改内容的性质，并评价删改是否合理，但不能披露被删信息本身。
- Anthropic 将评估关系分为三档：范围受限且发布需批准、更多访问且可独立发布，以及 METR 这类接近员工的内部访问。
- SecureBio 等其他合作仍处较早阶段，访问与发表权更有限；本次公告不是一份已完成的独立风险评估报告。

**为什么值得关注：** 外部评估的实际价值取决于可见信息、测试能力和发表自由。应分别追踪访问安排与未来公开结论，不能把入驻本身当成模型已获安全认证。
