## 研究

### 1. Zenity 披露 AWS Bedrock AgentCore 的权限隔离缺陷，可横向波及同区域所有 Agent

安全公司 Zenity Labs 公开了一组针对 AWS Bedrock AgentCore 的缺陷，统称 AgentCorruption。AgentCore 是 AWS 托管运行企业 Agent 的平台。Zenity 的核心结论是两点：一是运行 Agent 的沙箱没能拦住它去访问云实例的内部元数据服务，二是 AgentCore 默认给 Agent 分配的执行角色权限过大，不限于当前这个 Agent，而是覆盖同一账号、同一区域内的其他 Agent。两者叠加，意味着一个对外开放的 Agent 一旦被诱导越权，影响面可能扩大到整个区域的 Agent，包括读取源代码、私密对话和存储的凭据。Zenity 同时销售 Agent 安全产品，在这一领域有商业利益。

- Zenity 称问题出在平台层而非某个工具，单纯去掉 Agent 的联网工具并不能解决。
- 默认角色包含通配符权限和跨 Agent 的读写删权限，Zenity 认为这违反了“最小权限”原则。
- Zenity 于 2025 年 12 月 17 日向 AWS 报告。AWS 回应称已改进：自 2026 年 2 月 14 日起，新部署的 Agent 默认只用更安全的 IMDSv2；据 Zenity 更新，AWS 约在 8 月还收紧了默认执行角色，不再允许 Agent 调用其他 Agent、读取私密对话或从 Secrets Manager 取凭据。
- Zenity 仍建议企业不要依赖默认角色，自行为每个 Agent 配置权限更窄的自定义角色，尤其当对外和对内的 Agent 共用一个环境时。

**为什么值得关注：** 托管 Agent 平台把基础设施细节藏在背后，方便的同时也把隔离和权限边界的责任留给了平台。对用 AgentCore 的团队来说，教训很直接：别用默认执行角色，按最小权限给每个 Agent 单独配权。

来源：[Zenity Labs 技术博客](https://labs.zenity.io/post/agentcorruption-initial-imds-access) · [The Decoder](https://the-decoder.com/a-single-prompt-was-enough-to-hijack-every-ai-agent-in-an-aws-account-zenity-researchers-found/)

### 2. OpenAI 撤回 3 篇数学论文：一处符号错误连带推翻两篇依赖它的结果

OpenAI 10 月 7 日在其公开数学成果仓库 openai/math 的更新记录里宣布撤回三篇论文。起因是《Algebraicity of Weil classes on split abelian eightfolds》里的一处符号错误，使一个稳定化迹相消论证失效，而这个构造又被另外两篇论文用到，于是一并撤回。被撤的三篇现在都挂了说明错误的声明，并链接到归档版本。这批成果正是 8 月 OpenAI 宣称用未发布内部模型批量解决上百个数学问题后引发争议的那一批，撤稿也发生在数学界对“机器大批量产出证明”争论升温之际。

- 另外两篇被撤论文是《Algebraicity of Kuga–Satake Correspondences for K3 Surfaces》和《The rational Hodge conjecture for products of K3 surfaces》。
- 同一批更新里，OpenAI 还修订了另外 14 篇论文（证明修补、更正表述、厘清前提与依赖等），并因此连带更新了 13 篇引用它们的论文的引用和版本日期。
- 这次还新增 6 项形式化验证和 5 项其他补充，顶层结果的形式化比例达到 300/719，约 42%。
- 撤稿当天，由 Terence Tao 任主席的 Association for Human Mathematics 发出声明，呼吁抵制 OpenAI，理由是一次性放出 700 多份文件“不是学术展示，而是实力展示”；也有数学家认为抵制不现实。

**为什么值得关注：** 大模型批量产出的证明仍会因人类式的疏漏整体崩塌，一处符号错误就连累两篇依赖结果。这提醒使用 AI 生成形式化或半形式化证明的人，依赖链上游一旦出错影响会放大，独立验证和形式化比例仍是关键指标。

来源：[openai/math 更新记录](https://github.com/openai/math/blob/main/history.md) · [The Decoder](https://the-decoder.com/some-mathematicians-call-for-openai-boycott-after-ai-generated-proofs-flood-their-field/)

## 开源项目

### 3. Rust 版 TypeScript 编译器 ts-rust：Opus 5.5 从零写成，类型检查约为 Go 版的一半时间

开发者 Theo（ping.gg）公开了实验性项目 ts-rust（npm 包名 tsc-rs），把微软用 Go 写的原生 TypeScript 编译器（typescript-go）移植成 Rust。作者说他先用大量 OpenAI 模型尝试，花了超过 40 万美元 API token、写了 130 多万行 Rust，几个月也没突破约 84% 的兼容度；换成 Opus 5.5 后，模型从零重写，10 小时就有了可用的 v0，两周共花约 2.4 万美元跑到完整可用。作者坦言自己“没读过一行这些代码”。项目保持与上游某个固定版本对齐，用来做逐版本对比。

- 兼容性：对齐 microsoft/TypeScript 的 2026-09-29 版本（TypeScript 7.1.0-dev），18.17 万个移植自 Go 的测试全部通过；在 120 个开源仓库上，命令行输出与 Go 版只在少数已知问题上有差异。
- 速度：在 60 个开源项目上，类型检查用时约为 Go 版的一半（几何平均）；预览包在 CI 里未开 PGO 和 BOLT，实际比这个测得值更慢。
- 平台：目前提供 Linux x64（静态）和 macOS arm64，Windows 和 Linux arm64 尚未提供；内置 Effect 诊断，语言服务的快速修复、重构、补全等编辑器功能未移植。
- 许可证为 MIT，并保留所移植代码的 TypeScript（Apache-2.0）与部分 Go 标准库（BSD-3-Clause）声明。作者估计这件事如果专门去做，约 2 万美元就能完成。

**为什么值得关注：** 一个几十万行的真实编译器能被模型从零移植到另一门语言、还跑赢原版速度，说明“整库移植”这类过去被认为要数年的大工程，正在变成几周、几万美元的事。但作者“没读过一行代码”也点出风险：这类产物的长期可维护性仍是未知数。

来源：[ts-rust 仓库](https://github.com/pingdotgg/ts-rust)

### 4. TII 开源 Falcon-ASR：16 亿参数，主攻阿拉伯语和埃米拉提方言，五语共用一套权重

阿布扎比技术创新研究院（TII）10 月 7 日在 Hugging Face 发布 Falcon-ASR，一个 16 亿参数的语音识别模型，重点是阿拉伯语、尤其是埃米拉提方言，同时支持英、法、西、葡。阿拉伯语各地口音、录音条件差异大，方言的转写语料又远少于标准阿拉伯语，是识别的难点。Falcon-ASR 在公开的阿拉伯语榜单协议下，六个测试集的平均词错率（WER）为 20.92%，比该榜单快照里此前最好成绩 23.17% 低 2.25 个百分点。

- 在 TII 内部的埃米拉提方言评测上，WER 为 22.73%、字错率（CER）为 10.19%，WER 比次优的 Qwen3-Omni 低 4.07 个百分点。
- 英语用同一套权重转写，在 Hugging Face Open ASR 榜单的七个公开英语测试集上平均 WER 为 5.74%；五种语言共用权重，无需预先指定语言。
- 支持词级时间戳，把每个转写词对应到音频中的位置；训练时加入背景噪声、重叠语音、音乐、混响和电话失真等条件。
- 模型基于 TII 自家的 Falcon3-Audio，竞品数字取自榜单 9 月 30 日核对的公开平均值。

**为什么值得关注：** 对需要处理海湾方言、客服通话、会议录音的团队，这是一个可直接下载、体量不大的多语种选项。它也说明高质量 ASR 正在从少数几家向区域性机构扩散，方言覆盖成为差异化方向。

### 5. Anthropic 把 Claude Dashboards 和 Motion 开放公测，Docs、Slides、Design 转正

Anthropic 10 月 7 日为 Claude 新增两项 beta 功能。Dashboards 连接 BigQuery、Databricks、Snowflake 等数据平台或 Salesforce 等 CRM，用自然语言提问后自动生成会随数据更新的仪表盘，每个图表都能点开看背后的查询，并标注数据最后刷新时间。Motion 根据文字、图表和图片生成动画讲解，可当成短视频播放，也能在编辑器里改或导出 MP4。与此同时，此前 beta 的 Docs、Slides、Design 全部转正，所有套餐（含免费版）都能用。

- Dashboards 面向付费套餐开放；Motion 仅面向 Team 和 Enterprise。企业版里两者默认关闭，需管理员在组织设置里开启。

- Motion 用代码动画化你自己的文字、图表、形状和图片，不使用视频生成模型，因此没有生成的画面或 AI 人物；可在 Adobe、Descript、Runway 等工具里继续编辑。

**为什么值得关注：** Claude 的 Artifacts 从“聊天里生成一个网页”向“连企业数据的活仪表盘”和“可编辑的代码动画”扩展，开始和 BI 工具、视频工具的工作流交叉。对团队来说，快速探索性的数据提问和内部讲解动画多了一个入口，但正式分析仍要回到专业 BI 工具。

### 6. Hugging Face 的 ML Intern：在聊天里下单，隔天拿到一个为你定制的小模型

Hugging Face 工程师分享了用其 Agent 工具 ML Intern 的经历：他想要 Qwen-Image 2.1 自带那个 9B 提示词改写模型的小版本，于是把需求描述给 ML Intern，第二天就得到一个能在 CPU 上跑的 0.8B 版本，99.7% 的情况下输出合法、token 用量约为教师模型的四分之一，整个项目连同让 9B 模型标注 8797 条样本在内，只花了约 16 美元。接下来几天他用同样方式又做了五个模型。ML Intern 会规划工作、在花钱前先征求预算、先跑小测试再正式训练，并在 Hugging Face 的硬件上完成训练、评测和发布。

- 用法在 HuggingChat 里开启 ML-intern 模式后粘贴提示词；关键是让它先给基线分数、再跑冒烟测试，并设定花费上限（如“总花费不超过 12 美元，超出前先问我”），Agent 默认零预算、付费任务前必须获批。
- 柑橘病害识别：在 335 张测试图上，基座模型答对率 14.9%，用合并的 3017 张标注图微调 Qwen3.5-2B 两个 epoch 后升到 52.8%，计算成本约 1.90 美元。
- 六个项目总计约 103 美元；其中一个把图像编辑模型蒸馏到 4 步、再导出到浏览器和 ONNX 的项目约花 37 美元。
- 作者把七个项目的完整提示词公开在 GitHub（yvrjsharma/ml-intern-prompts），并强调提示词里专门列“已核实事实，不要重新推导”一节，好让 Agent 把预算花在干活上。

**为什么值得关注：** 这展示了一种新的工作方式：需要的小模型 Hub 上没有，就让 Agent 当天给你训一个，成本几美元到几十美元。对独立开发者和小团队，“没有就自己造一个专用小模型”正从口号变成当天可交付的事，但前提是会写带基线、冒烟测试和预算上限的提示词。

## 行业动态

### 7. Anthropic 推出 Cyber Mission：开源项目可免费报名 OSS Scanner，由最强模型定期扫漏洞

Anthropic 10 月 8 日宣布启动 Anthropic Cyber Mission，先做两件事，一是关键基础设施，二是开源软件。开源这一块推出 OSS Scanner，参照 Google OSS-Fuzz 的模式，报名的项目会定期收到 Anthropic 最强模型做的安全扫描，费用全免。与此前 Project Glasswing 的人工审核披露不同，OSS Scanner 的报告由模型生成后直接发出，不经人工复核，换来的是更快送达，代价是可能有误报或严重程度判错。关键基础设施方面则推出 Critical Infrastructure Defense Program（CIDP），给为电网、水务、交通提供安全服务的厂商配前沿模型、驻场工程师和威胁研究支持。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-09/7.svg" | relative_url }}" alt="OSS Scanner 的工作流程。维护者提 PR 报名 → 人工确认身份 → 断网沙箱中扫描 → 报告直接发邮件 → 定期复扫" loading="lazy"></figure>

- 每份报告包含漏洞利用的概念验证、原理说明，能给出修复时附上建议补丁。Anthropic 预计真阳性率在 90% 以上。
- 报名方式是由项目核心维护者向 GitHub 上的 anthropics/oss-scanner 仓库提 PR，添加 project.yaml，必填仓库地址、主要联系人邮箱和一个能离线构建项目的 Dockerfile；扫描 Agent 在断网的加固沙箱里运行。
- 可选的威胁模型文件用来告诉扫描器哪些输入算恶意、严重程度怎么定级、补丁写到什么程度。对这些未经人工验证的报告，Anthropic 不设 90 天披露期限，维护者可随时暂停或退出。
- 接收标准参照 OSS-Fuzz，优先面向远程攻击暴露面大、依赖方多的成熟项目，而且要求项目有能力消化报告；处理不过来的项目继续走人工验证的披露流程。Anthropic 称截至 10 月已人工审核过 6000 多份此类报告。
- CIDP 的首批合作方有 11 家，包括 Accenture、CrowdStrike、Dragos、Palo Alto Networks、Rockwell Automation 等。

**为什么值得关注：** 对人手有限的开源维护者来说，这是一份免费的前沿模型审计，但报告没有人工把关，报名前要想清楚团队能不能处理得过来。按 Anthropic 自己的说法，漏洞发现已经不是瓶颈，验证和修复才是。

来源：[Anthropic 公告](https://www.anthropic.com/news/anthropic-cyber-mission) · [OSS Scanner 说明页](https://red.anthropic.com/oss-scanner)

### 8. CrowdStrike 从攻击者暴露的 Claude Code 会话还原韩国银行入侵：ARTEX 加多款大模型

CrowdStrike 10 月 7 日发布报告，分析了 2026 年 9 月下旬到 10 月初针对韩国多家金融机构的一轮数据窃取。调查的突破口是攻击者自己留在公网开放目录里的材料，其中包含 Claude Code 的会话记录、ARTEX 的配置文件和 Claude 记忆文件，直接暴露了作案方法和工具。ARTEX 是今年 7 月在 GitHub 发布的中国产开源自主渗透测试工具，原本定位是红队评估。CrowdStrike 以中等置信度判断攻击者可能是讲中文、以牟利为目的，但未归因到具名组织。

- ARTEX 实例以 DeepSeek v4.1-flash 为主力模型，攻击者另用 GLM-5.3（智谱）和 Grok 4.6 跑额外的 Claude Code 会话；DeepSeek 很可能通过一个 API 代理/转售商访问。
- 开放目录里的一份 Claude Code 文档含中文渗透测试提示词，规定模型该如何执行；另一个开放目录暴露了香港 IP 上的主控基础设施与一个运行 ARTEX 的实例。
- 攻击者还曾问 Claude 哪里能卖韩国数据泄露信息、帮忙找韩国 Telegram 数据交易群，甚至让 Claude 根据这次行动战果写一份安全研究员简历。
- 据韩国媒体，9 月 27 至 30 日新韩、国民、Hana、BNK釜山等多家银行及储蓄银行被入侵，新韩银行被取走 25,727 条个人信息（含姓名、联系方式、年收入、贷款额度），国民和 Hana 分别泄露 119 和 89 条；手法疑为对面向贷款经纪的外围系统做 AI 自动化暴力猜测。

**为什么值得关注：** 这是一起已发生的真实事件，而非能力演示。它说明现成的开源渗透 Agent 配上几款便宜的大模型，已经足以让单个攻击者在短时间内对多家机构发起规模化入侵，外围、认证较弱的系统是最先被攻破的地方。
