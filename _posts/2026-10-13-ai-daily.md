### 1. Meta 发布 Muse Wonder：基础款接入 API，Full 向 Muse Code 订阅者开放

Meta 10 月 12 日推出 Muse Wonder 与 Muse Wonder Full，面向持续执行的个人和专业 Agent 任务。Muse Wonder 已通过 Meta Model API 和 Muse Code 提供，Full 则先提供给 Muse Code 订阅者。官方介绍跨会话保留相关信息的 Active Memory，以及在任务受阻时尝试其他路径、恢复错误的 Active Focus。公告中的能力表述属于厂商介绍，本轮不据此推断未公布的基准名次。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-13/1.svg" | relative_url }}" alt="Muse Wonder 本轮可用入口。Muse Wonder → Muse Wonder Full → Muse 应用" loading="lazy"></figure>

- Muse Wonder 在开发者入口已可用；Muse 应用中的接入将随后推进，先向订阅用户推出。
- Muse Wonder Full 的本轮可用范围为 Muse Code 订阅者，公告没有说它同样向所有 API 用户开放。
- Active Memory 用于跨对话保留和取回任务相关信息；Active Focus 用于目标跟进、错误恢复和必要的澄清。
- Meta 表示完整的补充安全评估报告将随后发布；本条不填写无法从可读公告核实的价格、参数量或基准数字。

**为什么值得关注：** 测试长期 Agent 时，除了任务成绩，还应核对记忆保留、用户澄清和重要操作前的确认行为。不同产品入口的可用范围需要分别确认。

## 开源项目

### 2. web-edit 0.1a0 发布：从手机直接编辑文件，无需经模型转述内容

Simon Willison 10 月 12 日发布 web-edit 的首个 alpha 版本，让用户通过网页浏览和编辑指定目录中的文件。作者的场景是远程与编码 Agent 协作时，想从手机直接修改文件，而不把凭据内容交给模型转述。编辑器使用 CodeMirror 6，也支持上传、下载和明确保存。它本身是文件编辑工具，不是自动保密或自动鉴权的 Agent。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-13/2.svg" | relative_url }}" alt="web-edit 的人工文件编辑场景。选择服务目录 → 在可信网络中访问 → 手机直接编辑并保存" loading="lazy"></figure>

- 初版入口为 uvx web-edit path/，可把指定文件夹作为服务目录。
- 当前仓库文档列出默认地址 127.0.0.1:9000，可改端口、监听地址和允许访问的主机名。
- 文档明确服务没有自身身份验证，面向可信本地网络或 Tailscale；主机名检查针对 DNS 重绑定，不等同于用户登录。
- 支持未保存提醒和外部修改检查；本轮只核验发布说明、作者介绍及仓库文档，未运行或暴露文件服务。

**为什么值得关注：** 在远程工作中，把模型协作与敏感内容的人工编辑分开有实际价值。使用这类工具前，应核对网络可达范围与服务目录，不能把无模型参与误解成无访问风险。

来源：[0.1a0 发布说明](https://github.com/simonw/web-edit/releases/tag/0.1a0) · [作者介绍](https://simonwillison.net/2026/Oct/12/web-edit/) · [仓库与当前使用边界](https://github.com/simonw/web-edit)

## 开发工具

### 3. GitHub 发布 Copilot 上下文指南：区分项目规则、skills、专用 Agent 与 MCP

GitHub 10 月 12 日发布入门指南，说明如何让 Copilot 读取项目惯例、复用流程并连接外部工具。文章把常驻规则、特定过程、专用角色和外部访问分别交给自定义指令、agent skills、自定义 Agent 与 MCP。它是一篇新发布的实践说明，不是四项能力当天首次上线的公告。重点是把项目知识放在适当位置，减少每次会话重新解释。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-13/3.svg" | relative_url }}" alt="Copilot 项目上下文的四种用途。自定义指令 → Agent skills → 专用 Agent 与 MCP" loading="lazy"></figure>

- 仓库通用规则放在 .github/copilot-instructions.md；按路径适用的规则放在 .github/instructions，并使用 applyTo 指定范围。
- 可复用过程放在 .github/skills 的独立文件夹中，由 SKILL.md 描述何时使用、步骤及辅助资源。
- 较复杂的专用任务可通过 .github/agents 中的角色定义组织目的、指令与工具。
- MCP 连接仓库以外的数据与工具；增加连接能力并不意味着结果自动通过测试或验收。

**为什么值得关注：** 项目应把长期标准与按需过程分开维护，避免一份常驻指令塞入所有任务。外部工具调用后仍需按项目自己的测试和质量规则验证。

来源：[GitHub 官方实践指南](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-how-to-teach-copilot-about-your-codebase/)

## 行业动态

### 4. NVIDIA 向 OCP 贡献 Vera Rubin 机架设计，MGX 1.2 支持最高 250kW 部署

NVIDIA 10 月 12 日在 OCP Global Summit 宣布，将 Vera Rubin 机架和计算托盘设计通过 MGX 开放架构贡献给社区。MGX 1.2 扩展液冷、电源和互连接口，目标是让不同系统制造商按共同设计生产和集成。官方还公布 DSX AI Factory 的开源运营组件，覆盖网络配置、集群健康验证和机架管理。这里的开放对象是基础设施设计和软件组件，不是 GPU 芯片设计或新模型权重。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-13/4.svg" | relative_url }}" alt="MGX 1.2 开放设计的集成范围。计算托盘与机架 → 电源、液冷与互连 → 运营组件" loading="lazy"></figure>

- MGX 1.2 支持最高 250kW 的机架部署设计，并增加原生 19 英寸设备支持和高密度机架设计。
- 规范包括机架级盲插液冷、可互操作互连和液冷 5000A 母排；这是设计支持能力，不是每个机架的实际用电量。
- Vera CPU 机架设计面向工具调用、编排与沙箱执行，与大规模训练和推理的 Vera Rubin NVL72 分工不同。
- DSX 开源组件涉及交换机配置、集群就绪验证、机架固件管理和裸金属部署；厂商收益表述不作为独立实测数据。

**为什么值得关注：** AI 基础设施的扩展不仅受 GPU 算力限制，也取决于供电、液冷、互连和运维接口。开放参考设计可为多厂商集成提供共同边界，但仍需项目级验证。
