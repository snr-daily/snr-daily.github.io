### 1. Moonshot 推出 Kimi K3.1 Pro：支持百万上下文，完整权重计划 11 月 4 日前发布

Moonshot 推出 Kimi K3.1 Pro 与 Highspeed，现已接入 Kimi、Kimi Work、Kimi Code 和 API。模型基于 K3 扩大后训练，重点改善编程、3D 创建与多步工作，官方称其为 3T 级模型。文档列出 1048576 token 上下文，完整权重仍计划在 11 月 4 日前发布。托管可用与权重已开放是两个阶段，本期不将未来计划当作已有下载。

**为什么值得关注：** 有长任务需求的团队可先比较完成质量、工具开销与总费用。自部署仍需等待实际权重、运行配置和许可文件，不能仅据“3T 级”估算本机可运行性。

### 2. Block 展示 Dessa 全双工语音模型：仅用人类语音训练，当前开放候补

Block 的 Dessa 团队展示从人类对话音频训练的语音到语音模型，称未使用文本或预训练模型作为起点。它可同时收听和发声，尝试保留语调、笑声、停顿与接话节奏，而不先把所有交流压成文字。官网提供录音示例、候补名单及安全研究者早期访问入口。页面没有给出公开权重或通用可调用 API，本期将其视为研究展示。

- 团队称训练使用一套 NVIDIA GB200 NVL72，并称可在 MacBook Pro M4 Max 或更高配置本地运行；未披露足以复现的参数量、内存需求与完整训练配方。
- 示例由真人与模型实时对话录制、字幕后加；它们不是受控质量测试，也不能证明任意噪声、语言或说话人场景都有效。
- 页面称推理快于实时，但没有统一延迟分位数与测量条件，本期不与其他语音服务绘制速度排名。
- 团队征求少量外部安全研究者参与，模型的风险与情绪理解能力仍需独立评估；未进行本机安装验证。

**为什么值得关注：** 纯音频学习为语音交互提供了另一条研究路线。开发者仍需等候访问、接口和明确资源规格，再测试打断、延迟、识别误差及授权边界。

来源：[Block：Dessa 官方展示与访问方式](https://block.xyz/dessa)

## 研究

### 4. Anthropic 与 Theorem 用 Claude 生成形式化证明：覆盖 123 个库的 239 个入口

Anthropic 10 月 22 日报告与 Theorem 的形式化验证实验：把 OSS-Fuzz 入口及编译后的 RISC-V 程序转为规范，让 Claude 写证明，再由 Rocq 内核检查。团队称已为 123 个库的 239 个入口证明特定条件下不会触发崩溃。主要范围是固定内存预算、单线程静态 Linux/RISC-V 程序与小于 64 MB 输入。它证明的是明确规范，不是整个软件在所有环境下没有漏洞。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-24/4.svg" | relative_url }}" alt="如何把模糊测试转为可检查证明。固定程序与规范 → Claude 生成证明 → Rocq 内核检查" loading="lazy"></figure>

- 团队报告生成约 1.8 亿行 Rocq 证明；检查器核验推导，但规范是否覆盖真实机器与业务要求仍需要审查。
- 未证明每个库的所有入口，ASan 也不能覆盖所有内存安全问题；x86、ARM、动态链接和多线程部署不能直接继承该结论。
- 修补程序后规范会重新生成，因此需同时审查补丁是否保留行为，防止通过删掉功能使性质平凡成立；团队称记录并审计了这类修改。
- 公开的是部分证明与语义组件，可能泄露未修复缺陷的证明未全部发布；本期未运行独立证明检查。

**为什么值得关注：** 可复核的证明产物把模型建议与可信结论分开。采用时先固定定理、构建产物与机器语义，再检查覆盖缺口和补丁行为。

来源：[Anthropic：形式化验证实验、范围与局限](https://www.anthropic.com/research/formal-verification)

### 5. Ai2 公布 LitPivot：按提案片段组织文献，用证据支持研究方向修订

Ai2 与宾夕法尼亚大学研究者 10 月 23 日介绍 LitPivot，将研究构思的修改与文献选择放在同一界面。它把提案分为问题、贡献与评估计划，按当前编辑片段组织相关论文，附证据摘录提出修订。17 名研究者的实验中，专家认为使用该系统形成的提案更有文献依据。这里评估的是构思与文献的关联，并非证明产生了可发表的新发现。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-24/5.svg" | relative_url }}" alt="LitPivot 如何支持提案修订。选择正在编辑的片段 → 选择文献并查看证据 → 人工修订并重新检索" loading="lazy"></figure>

- 论文由 Asta Paper Finder 检索，研究者选择用于评估的文献，可接受、编辑或拒绝建议；修改后重新排序相关文献。
- 实验对照为文本编辑器加 AI 问答工具，两种条件使用同一论文集合；两名不知道使用何种系统的领域专家评分。
- 新颖性、实用性与理解提升包含参与者自报结果，不能与专家对文献依据的评分混为同一指标。
- 后续另有 5 名研究者各用 30 分钟处理自己的项目，样本较小；本期未实际操作该系统或验证可获得的产品权限。

**为什么值得关注：** 研究辅助可以围绕“哪些证据改变了问题、贡献和评估”留下可追溯记录。生成的修改意见仍需读原文和专家判断，不能用自动新颖性评价替代研究审查。

来源：[Ai2：LitPivot 工作流、用户研究与限制](https://huggingface.co/blog/allenai/litpivot)

### 6. Hugging Face 开放 Trainium 模型查询：公开短生成结果、软件版本和复跑脚本

Hugging Face 10 月 23 日发布 torch-neuronx model support 查询工具与数据集。开发者可按模型、任务、Neuron 编译器和 Transformers 版本查看是否未经修改即可运行，并取得实际 run.py。页面记录芯片核数、包含编译的总耗时和峰值设备内存。此次新增的是可查询测试证据，不重复报道此前 TorchNeuron 后端发布。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-24/6.svg" | relative_url }}" alt="Trainium 查询如何支持部署验证。匹配模型与软件版本 → 理解短生成检验 → 复测真实任务负载" loading="lazy"></figure>

- 当前仅测试 Transformers 的 text-generation 与 image-text-to-text，且模型须可装入最多 4 个 Trainium2 设备、16 核；其他任务仍是扩展计划。
- 每次生成 32 token；单核与同检查点 CPU 输出对比，分片运行由小模型判断英文是否流畅，因此 PASS 的检验强度因运行方式不同。
- PASS 不证明吞吐、长生成或复杂多模态任务质量；未优先测试不等于不兼容，页面会标明跳过原因。
- 公开数据按编译器与库版本保存结果、错误和脚本，NEFF 缓存也需匹配编译器版本；本期未启动付费实例。

**为什么值得关注：** 部署前可以先按精确版本查证据，再在目标负载复跑。应把编译时间、生成吞吐、精度和内存分别测量。

### 7. Claude Enterprise 合并聊天与 Cowork：云端继续执行，新增 Efficient mode 管理用量

Anthropic 10 月 23 日将统一聊天与 Cowork 体验正式扩展到 Claude Enterprise。用户可在同一对话中从问答转为代码或文件任务，关闭电脑后云端工作仍可继续，并可跨网页、桌面和手机接续。管理员按角色管理访问，Efficient mode 将使用限制在 Sonnet 与 Haiku。此前 Pro 和 Max 已在 9 月合并，本次新增范围是企业版。

- 企业云会话各有隔离虚拟机，默认关闭网络外连，连接器凭据保留在沙箱外；实际权限仍由组织设置决定。
- 聊天、项目、连接器、技能与插件延续到新体验，仍沿用 SSO 与 Compliance API 等企业控制。
- 计费继续按用量，管理员可设置组织、组、成员限额及组共享月度预算；Agent 工作可能比简短聊天消耗更多 token。
- 使用 Claude Code 零数据保留、HIPAA-ready 配置或客户管理加密密钥的组织继续保留现有配置，不能写成所有企业均自动迁移。

**为什么值得关注：** 企业上线时应同时验收角色、外连策略、跨端任务状态与预算。入口合并降低选择成本，但云端持续运行仍需要明确的费用与权限边界。
