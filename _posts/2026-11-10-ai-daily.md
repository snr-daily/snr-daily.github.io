## 模型发布

### 1. Anthropic 发布 Fable 5.2 与 Mythos 5.2，标准输入价为每百万 token 8 美元

Anthropic 于 11 月 9 日升级 Fable 与 Mythos，面向复杂编程、推理和科学技术任务。两者使用同一底层模型，但访问范围和防护设置不同。标准模式输入与输出价格分别为每百万 token 8 和 40 美元，另提供更贵的快速模式。

- Fable 5.2 面向各平台用户开放，Claude Platform 的模型名为 claude-fable-5-2；Mythos 5.2 面向通过网络安全或生命科学验证计划的组织。
- 快速模式输入与输出分别为每百万 token 16 和 80 美元。官方称 token 生成最多加快 2.5 倍，不等于每个任务的端到端耗时都减少相同比例。
- Fable 对部分高风险网络安全与生物任务有额外限制，可能转由较早的 Opus 模型响应。评估此类任务时需记录实际模型与回退。
- 官方仍建议多数日常编程和知识任务先使用 Opus 5.5，再按任务复杂度选用 Fable、Mythos 或更小模型；本期未独立复现发布页实验。

**为什么值得关注：** 可以把复杂任务交给新模型做针对性评估，同时比较标准与快速模式的总 token、完成时间和费用。访问权限与回退行为也应纳入测试。

### 2. Meta 发布 Muse Ember，短提示输入价为每百万 token 0.10 美元

Meta 推出 Muse Ember，面向工具调用、代码子任务、信息抽取和长文档处理等高频工作。模型在 Muse Code 与 Meta Model API 提供，模型名为 muse-ember-1.0。官方列出 1M 上下文和最多 512K 输出，并按提示长度采用不同价格。

- 提示不超过 200K token 时，每百万输入、缓存输入和输出分别为 0.10、0.004 和 0.50 美元；更长提示分别升至 0.30、0.012 和 1.50 美元。不能把低档价直接用于整段百万 token 输入。
- Meta 官方介绍文本、图像、音频和视频理解；Google Cloud 当前预览文档仅列文本与图像输入、文本输出，接入能力需按具体平台核对。
- Google Cloud 列出最大输入 1,048,576、最大输出 524,288 token，工具调用、结构化输出与推理均为预览能力。
- Meta 评估说明区分内部共同框架与外部编码结果；后者保留不同产品的运行框架，不能把榜单差异完全归因于底层模型。

**为什么值得关注：** 高频子任务可按真实请求长度估算费用，再测试工具调用与结构化输出。平台入口、长提示加价和失败重试会影响实际成本。

### 3. 字节发布 Seedream 5.5，支持连续图像编辑与原生透明素材

字节 Seed 团队发布 Seedream 5.5，重点改进多轮编辑的稳定性、透明素材生成和文字渲染。模型可原生生成带 alpha 通道的 RGBA 图像，包括完全与部分透明区域。官方展示同一人物图像连续编辑 100 轮，上一轮输出作为下一轮输入。

- 团队称针对性训练改善了未编辑区域的保留，减少多轮修改中的色偏和细节退化。100 轮是官方演示条件，不代表任意图像均可无损编辑 100 轮。
- 透明素材可由文本或参考图生成，便于独立排版和合成。产品页也展示提取对象后输出单独 RGBA 图层的用法。
- 团队在 MagicArena 的电商、营销、影视、游戏、办公和时尚六类场景做主观质量与可用性评估，比较对象为 Seedream 5.0 Pro；本期未复现评估。
- 发布说明给出严重文字损坏率 0.4%、轻微损坏率 1.7%，来自覆盖中英文和密集小字的测试。这些是特定评估指标，不能换算为所有文字生成的正确率。

**为什么值得关注：** 需要反复修改同一画面或复用透明素材的团队，可重点检查未编辑区域、alpha 边缘和密集中文。演示与自报指标仍需用实际素材验证。

来源：[Seed 官方发布、演示与评估口径](https://seed.bytedance.com/en/blog/more-realistic-images-more-stable-editing-across-100-rounds-introducing-seedream-5-5) · [Seedream 5.5 官方能力页](https://seed.bytedance.com/en/seedream5_5)

## 研究

### 4. Amazon 详解 HOPE：按专家协同关系剪枝，50% 剪枝实验保留编程表现

Amazon 研究者在 11 月 9 日的技术文章中介绍 HOPE 专家剪枝方法，补充已公开论文的原理与使用流程。与独立给每个专家打分的方法不同，HOPE 把专家之间的共同激活关系纳入剪枝选择。作者报告，在 Qwen3.5-35B-A3B 的一组 50% 专家剪枝实验中，HOPE 的 SWE-Bench Pro 得分为 42.3，未剪枝模型为 41.8。

<details class="snr-data"><summary>查看数据</summary><table><thead><tr><th>项目</th><th>SWE-Bench Pro 得分</th></tr></thead><tbody><tr><td>未剪枝</td><td>41.8</td></tr><tr><td>REAP，剪枝 50%</td><td>36.2</td></tr><tr><td>HOPE，剪枝 50%</td><td>42.3</td></tr></tbody></table></details>

- 方法先在校准数据上记录门控权重、输出范数和两两共激活统计，形成交互矩阵；再通过二次规划的连续松弛求剪枝集合，最后生成更小检查点。
- 同一组 Qwen3.5-35B-A3B、50% 剪枝设置下，一阶基线 REAP 得分为 36.2。50% 指被删专家比例，不是整模型参数或显存恰好减半。
- 作者评估三款模型、两组校准数据和 10% 至 50% 的剪枝率。40% 至 50% 时优势较明显；10% 至 20% 时部分一阶方法仍有竞争力。
- 当前算法按层独立处理两两交互，未完整覆盖跨层或三元以上合作关系。代码仓库还要求模型使用特定堆叠专家布局，并列出已测试架构。

**为什么值得关注：** 压缩 MoE 时，保留协同专家是可测试的选择依据。收益需要在目标任务和校准分布上验证，同时分别记录权重大小、内存、速度与任务质量。

## 行业动态

### 5. OpenAI 公布 Control Room，在推理层停止研究任务的模型输出

OpenAI 介绍已部署在研究基础设施中的 Control Room，用于追踪研究推理任务并在需要时停止输出。任务注册 job_id，推理引擎在满足请求前检查该任务是否仍获授权。官方称从收到停止指令到阻止进一步进展的最长时间为 35 秒，延迟来自授权缓存。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-10/5.svg" | relative_url }}" alt="Control Room 如何停止任务输出。研究任务注册 job_id → 推理引擎检查授权 → 停止后拒绝进一步输出" loading="lazy"></figure>

- 研究任务启动时获取 job_id，之后向推理引擎发出的采样请求携带该标识；停止后，引擎拒绝继续为该任务产生模型输出。
- 任务进程本身可能仍存活，共享推理引擎也可继续服务其他获授权任务。系统控制的是模型输出权限，不能理解为删除进程或撤销已执行动作。
- 停止机制放在较集中统一的推理层，避免完全依赖频繁变化的任务代码自觉检查。监控系统也可向 Control Room 提交停止指令。
- 服务不可用时拒绝推理的 fail-closed 配置，已覆盖前沿模型研究任务，其余研究任务将在随后几天完成。该说明不是给外部 API 客户承诺通用停止接口。

**为什么值得关注：** 对多任务 Agent 基础设施，统一任务标识与推理授权提供了可参考的控制点。实际设计仍需另行处理已发出的工具操作、缓存窗口和服务恢复。
