模型权重编辑与推理循环

01研究 · 11.02 发布

MIT CSAIL 用 Astra 编辑 Qwen3.5-0.8B 权重，减少推理循环

MIT CSAIL 研究者让 GPT-6 Astra 检查 Qwen3.5-0.8B 的权重并直接修改部分参数。作者报告，在相同采样设置下，MATH-500 得分从 7.9% 升到 48.1%，触及输出上限的比例从 93.0% 降到 33.1%。实验说明减少重复输出能让这个小模型完成更多题目，数学推理能力本身的变化还需要另行衡量。

编者解读

小模型评测可以同时记录任务得分和输出截断率。只看最终得分，很难区分答题能力和能否在预算内结束推理。

MIT CSAIL 作者实验报告 ↗
展开核实细节与数据口径 ＋
  • Astra 在 Python 环境中分析权重，定位到第 15 和 19 层 MLP 写入的方向，共修改 131072 个权重，约占模型权重的 0.016%。
  • 对比使用温度 0.6、top-p 0.95、top-k 20 和 presence penalty 1.5。MATH-500 每题采样四次，输出上限为 32768 token。
  • 这里的 50 次前向计算是作者报告的编辑实验预算。相同实验还报告 IFEval 从 21.0% 升至 62.3%。
02

Git 扩容、代码审查与模型 CLI

03开发工具 · 11.02 发布

OpenAI 公布 Pando 架构，内部 Git 推送中位延迟下降近 80%

OpenAI 介绍为大型代码仓库构建的 Git 服务 Pando。系统将 Git 协商与可复用 packfile 的传输分离，通过区域缓存服务大量重复下载。团队先以读写代理接入旧系统，再分阶段迁移流量，报告推送中位延迟下降近 80%。

编者解读

大量 Agent 并发拉取同一仓库时，可复用的传输产物能减少服务端重复生成数据。延迟数据来自 OpenAI 内部迁移。

OpenAI 工程文章 ↗
展开核实细节与数据口径 ＋
  • Express 服务缓存对象存储中的 packfile，另有服务缓存元数据。团队用一致性哈希分配 packfile 请求，报告缓存命中率超过 99%。
  • 使用 packfile URI 和区域缓存时，团队验证 clone 与 fetch 可跑满 10 Gbps 网络链路。
  • 单小时传输曾超过 57 TB 的 Git pack，其中超过 99% 的字节来自本地磁盘缓存。该数字与请求缓存命中率采用不同口径。
04开发工具 · 11.02 发布

Qodo 插件把仓库规则和改动审查带进 Codex 会话

OpenAI 发布 Qodo 的代码审查案例。Codex 可以在改代码之前读取 Qodo 提供的仓库规则和历史 PR 信息，改动完成后在同一会话收到独立审查意见。案例描述了跨仓库依赖分析的用途，未提供可比较的缺陷检出率。

编者解读

把审查提前到 PR 之前，可以让开发者在修改上下文还完整时核对问题。跨服务规则仍需用实际仓库覆盖情况验证。

OpenAI 与 Qodo 案例 ↗
展开核实细节与数据口径 ＋
  • 插件通过 Qodo 的 Agentic Toolbox 提供代码库知识、组织规则与审查能力。
  • 跨仓库场景包括服务分别托管在不同 Git 提供商，或通过 Kafka 连接。
  • 审查可以在开发者创建 PR 前进行，结果直接返回给 Codex。
02开源项目 · 11.02 发布

LLM CLI 0.37 增加 OpenAI 兼容端点配置命令

Simon Willison 发布命令行工具与 Python 库 LLM 的 0.37 版，汇总约两个月的功能与修复。新版提供命令注册使用 OpenAI 兼容接口的模型，并更新了未自行设置时的默认模型。嵌入接口也开始接受不同二进制输入的内容类型。

编者解读

使用同一套 CLI 切换兼容端点时，注册过程更直接。依赖默认值的脚本可以显式指定模型，便于复现结果。

Simon Willison 的 0.37 发布说明 ↗
展开核实细节与数据口径 ＋
  • 使用 llm openai endpoint add 配置额外的 OpenAI 兼容端点。
  • 工具新增 gpt-6.1-sol 与 gpt-6.1-terra 的模型支持。未指定自定义默认值时改用 gpt-6-luna。
  • 内容类型可区分不同二进制输入，作者以能处理文本、音频、图像和视频的 Gemini Embedding 2 说明这一接口改动的用途。
