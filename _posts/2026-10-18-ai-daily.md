### 1. DeepSeek 更新 V4.1 Flash 1017：提升编程评测，并开放搜索与抓取 API

DeepSeek 10 月 17 日将网页、App 和 API 更新为 V4.1-Flash-1017，调用仍使用 deepseek-flash，模型 API 价格保持不变。官方称新后训练改善了推理、代码、视觉和 Agent 任务，并减少部分任务的输出长度与耗时。模型权重已提供下载，许可为 MIT；这些性能结论来自厂商评测，本期未独立复跑。同日开放的 Search 与 Fetch 是按请求计费的独立接口，需要和模型 token 费用分别计算。

- 建议升级 DeepSeek Harness 至 0.2.1-rc.1 或以上；游戏与 3D 建模案例是官方选取的演示，不代表任意完整项目都能一次完成。
- 模型卡给出 1M token 上下文，并提供独立 Python 提示编码实现；本次没有 Jinja 格式聊天模板，接入时要核对工具调用与思考模式编码。
- 中文公告列出 Search、Fetch 各为每千次 5 元。DeepSeek Harness、Claude Code、Codex 经 DeepSeek API 服务端调用的这两类工具当前未计费，将于北京时间 11 月 1 日 00:00 开始按次收费。

**为什么值得关注：** 既有 API 用户会随别名切到新版，应复测自己的代码任务、输出长度和工具轨迹。预算也要单独纳入搜索与抓取请求，不能只看每百万 token 单价。

### 2. 上海 AI 实验室公布 Atria Dawn 正式版结果：API 标注 512K，完整权重待发布

上海 AI 实验室的 Atria Dawn 面向科研与工程中的连续工具使用、多步交付和失败恢复，基于 744B 参数的 GLM-5.2 MoE 底座。当前官网与仓库已给出正式版结果和托管 API 接入方式，API 文档列出 512K 上下文。完整权重及 FP8 版本仍标为 Coming soon，可下载链接指向此前的 Preview。仓库下载表仍写 256K，因此应分别核对托管服务与未来本地权重的规格。

### 3. Elorian 发布 Glimpse 视觉推理预览：可放大图像、重看视频后再回答

Elorian 10 月 16 日发布 Glimpse，强调在推理过程中回到图像和视频证据，而不只依赖第一次观察。平台可展示模型放大局部、提高短片段采样密度和追踪特征的过程。官方已给出 API 和聊天入口，定价为每百万输入 token 0.60 美元、输出 3 美元。模型仍属研究预览，厂商也把 token 效率列为下一阶段重点。

- 官方示例用重新观察来区分相机平移与镜头切换，或追踪固定特征判断列车减速；页面区分录制的模型轨迹与人工审核参考答案。
- 其评测使用不同模型的原生 Agent 框架和推理强度，部分视频任务的设置也不同；不能把表格当成完全统一执行条件的横向实测。
- 模型基于开放权重底座做后训练，但本次公告只提供托管访问，没有因此宣布 Glimpse 自身权重开放下载。

**为什么值得关注：** 对视频审阅，值得试验的是模型能否定位不确定片段并给出可回查的证据。实际成本还取决于重看次数和 token 消耗，单价较低不自动意味着整项任务更便宜。

## 研究

### 4. Anthropic 用 Claude 优化量子电路：通过程序评估减少门数与存储开销

Anthropic 10 月 16 日介绍 Claude Mythos 5 的量子电路设计研究，给模型八类计算原语的规格和自动评估器。模型用代码提出电路，评估器检查正确性并按量子比特与门数评分，再把反馈送回下一轮。团队报告找到新的资源折中方案，其中一种点加电路比此前最小设计多用 12% 量子比特，但门数约为其十七分之一。这里比较的是电路资源，不是量子硬件上已经完成的端到端加速。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-18/4.svg" | relative_url }}" alt="量子电路设计的自动反馈闭环。提出电路 → 程序验证与评分 → 修订方案" loading="lazy"></figure>

- 点加任务经过约 53 小时探索，期间有初始要求和少量拓宽思路的人工提示；关键分支恢复公式经过数值检查和 Lean 形式化验证。
- 另一项 Reed–Solomon 解码工作改用更适合固定步骤的算法，并通过重建临时状态减少存储，报告门数降至此前构造的约十二分之一。
- 解码器保留有限异常存储，约万分之一运行会失败，处于该任务允许误差范围；结果依赖问题设置与容错条件。
- 这些改进尚不能代替量子硬件控制、纠错和完整系统验证。团队也观察到模型偏好既有方法，需要有意识拓宽搜索。

**为什么值得关注：** 这类任务适合“提出方案—程序验证—资源评分”的闭环，价值在于检查器能明确拒绝错误设计。迁移到其他科研任务时，也应先建立可靠的验收指标。

来源：[Anthropic：量子电路设计研究与限制](https://www.anthropic.com/research/designing-efficient-quantum-circuits)

### 5. PS5LM 将 llama.cpp 接入 PS5 GPU：在局域网提供兼容模型接口

开源项目 PS5LM 把 llama.cpp 的 Vulkan 后端接到 PS5 的 RDNA 2 GPU，让主机作为局域网模型服务器。项目提供 GGUF 加载、电视端界面和浏览器聊天，并兼容 OpenAI Chat Completions 与 Anthropic Messages 接口。它需要已经具备相应自制软件运行环境的主机，普通零售系统不能直接安装。本文核实当前仓库功能，不将本轮社区发现时间当作项目首次发布日。

- 仓库称模型与上下文可使用约 11.4 GB 共享内存，规划器依据 GGUF 和剩余内存选择上下文及缓存配置。
- 作者在 PS5 Slim 上报告 Qwen 3.5 9B、Q4_K_M 约 55 token/s；该数字来自项目方，未在本机或其他型号独立复测。
- 带图像投影组件的受支持模型可接收图片；当前说明还列出类型化决策接口，不表示任意 GGUF 都自带视觉或决策功能。
- 主项目采用 GPL-3.0-or-later，llama.cpp 保留 MIT 许可；运行速度还取决于模型量化、上下文和具体主机条件。

**为什么值得关注：** 这个项目展示了把现有消费硬件接入标准模型接口的可行路径。评估家庭推理服务器时，要同时看软件前提、可用内存和实际负载，不能只比较峰值生成速度。

来源：[PS5LM：官方仓库、接口与硬件条件](https://github.com/cobanov/PS5LM)

### 6. llmspeed 用网页模拟本地模型响应：区分实测、推导与硬件预测

llmspeed 允许选择硬件、模型与量化方式，在浏览器里体验预计的首 token 等待和逐字输出速度。它支持两套配置并排比较，也提示模型能否装入内存或需要部分卸载。网站数据同时包含社区实测、相近配置推导和硬件规格预测，每项应结合证据标签阅读。这是购买前的交互估算工具，浏览器播放速度不构成对用户电脑的现场测试。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-18/6.svg" | relative_url }}" alt="llmspeed 的速度展示如何形成。选定配置 → 获取或估算数据 → 模拟响应节奏" loading="lazy"></figure>

- Measured 表示对应硬件、模型和量化的实测；Derived 来自相近配置插值，Projected 则按规格预测，可能涉及尚未发布的硬件。
- 估算器把生成速度与内存带宽、提示处理与计算能力关联，再按后端效率、上下文和部分卸载修正；这些是简化模型。
- 容量规划计入权重、KV 缓存和运行开销；Mac 可用统一内存约按 75% 估计，独显约按 93% 显存估计，是工具假设而非系统保证。
- 当前限单设备，不模拟多 GPU。项目指出驱动、引擎版本、功耗和温度均会改变结果；代码采用 MIT 许可。

**为什么值得关注：** 它能把 token/s 变成更直观的等待体验，帮助缩小候选范围。最终选型仍应使用同一模型、量化、上下文和并发在目标设备上实测。

来源：[llmspeed：在线工具与数据说明](https://llmspeed.dev/) · [llmspeed：估算方法、标签与限制](https://github.com/nicorobinreal/llmspeed)
