## 研究

### 1. Simon Willison 用 Claude 比较 SQLite 扩展：优化 C 解析路径后缩短每行耗时

Simon Willison 发布一项 Claude Opus 5.5 辅助完成的 SQLite 扩展实验，让 C 与两种 Rust 扩展实现相同的 parse_number() 功能。初版 C 在混合数据上慢于 Rust，改写小数解析的快速路径后，报告中的净耗时由 67.3 降至 19.2 纳秒每行。完整报告与代码由模型生成，数字是作者发布的实验记录，本期未独立复现。

- 四种实现统一处理货币符号、逗号、百分号和前导负号。百分号只被去掉，例如 12.5% 输出 12.5；不是将其换算为 0.125。
- 测试在 2 vCPU Linux x86-64 虚拟机、SQLite 3.53.1 上进行。每组为 200 万行，取 15 轮中最快值，再减去同数据的基线扫描耗时。
- 混合数据上，初版 C、优化 C、rusqlite 和 sqlite-loadable 分别为 67.3、19.2、45.9 和 40.5 纳秒每行。它们是净耗时估计，不是完整查询的端到端延迟。
- 报告提供 40 个手写用例和约 800 万次模糊对比，检查数值与类型一致性；C 的少见回退路径仍受宿主区域设置影响。这些测试不构成对所有输入的正确性证明。

**为什么值得关注：** 这项实验展示了从性能差异追到具体解析路径、再补充对比测试的过程。结论限于这组实现和测试环境，不能概括为 C 与 Rust 的普遍速度排序。

## 开源项目

### 2. Avalon 发布 Windows 构建，以系统内存分担 Qwen3.8-Flash-Next 专家权重

社区维护者 newmilltechnology 发布 Avalon 的 Windows 原生构建，面向 NVIDIA GPU 上的 Qwen3.8-Flash-Next。该方案把专家权重放在系统内存，其余部分在 GPU 上运行。作者仅报告在 RTX 5070 Ti 16 GB、Ryzen 9 9950X 和 192 GB DDR5 的机器上测试，16 GB 显存不能等同于整机内存要求。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-09/2.svg" | relative_url }}" alt="Avalon Windows 构建的部署条件。准备模型与系统内存 → 配置 Windows 与 NVIDIA 环境 → 按量化版本启动" loading="lazy"></figure>

- windows-v1 于 11 月 8 日发布，基于 Avalon main 的 12abd35 提交，加上 MSVC 构建、默认 CUDA_MODULE_LOADING=EAGER 和 CUDA graphs 挂起修复；三项修复已向上游提交。
- CPU 代码要求 AVX2，GPU 构建覆盖 RTX 30、40、50 系列。需要支持 CUDA 13.4 的 NVIDIA 驱动与 x64 Visual C++ 运行库；作者使用驱动 617.42 测试。
- 安装包提供六组量化版本的启动器，但不包含模型文件。说明要求系统内存大于模型文件，不能按显存容量单独判断能否运行。
- 作者在上述机器上报告，同文件下生成约快两倍，长提示读取快 7.5 至 12 倍；这是特定配置下的自报结果，本期未下载程序或复测，也未验证其他硬件。

**为什么值得关注：** 对显存较小、系统内存较大的 Windows 主机，这提供了一个可复现的部署候选。评估时需要固定模型量化、内存、驱动与上下文长度，再分别检查读取和生成速度。

来源：[Windows 构建与测试条件](https://github.com/newmilltechnology/Avalon/releases/tag/windows-v1) · [维护者在 llama.cpp 社区的说明](https://github.com/ggml-org/llama.cpp/discussions/31868)

## 开发工具

### 3. CrewAI 1.15.38 改用 gpt-6-luna 默认模型，并修正运行失败状态

CrewAI 发布 1.15.38，将框架默认模型统一改为 gpt-6-luna。更新增加从 Agent 输入的电子表格网址读取全部行的工具能力，也调整评估与运行命令的失败处理。未显式固定模型的项目，需要核对升级后的实际调用目标。

- crewai eval 新增 --no-open，适合不自动打开浏览器的环境；评估用量追踪增加目标标签和每次评估的标识。
- 评估异常退出会计为 run_failed，项目脚本失败时 crewai run 返回非零退出状态，便于上层任务判断失败。
- 评估开启追踪并创建项目 .env 时，文件权限限制为所有者访问。追踪分享提示同时调整为回车表示同意，并解释用途。
- 发布于 11 月 8 日 19:39 UTC，即北京时间 11 月 9 日 03:39。此次框架默认值更新本身不提供模型能力或成本对照。

**为什么值得关注：** 升级后应检查默认模型、失败退出和追踪分享选项，避免定时任务把失败当成功；需要稳定复现的项目可显式记录实际模型配置。

来源：[CrewAI 官方 1.15.38 发布说明](https://github.com/crewAIInc/crewAI/releases/tag/1.15.38)

### 4. Activepieces 0.93.0 为 MCP 客户端加入 OAuth2 与授权信息发现

Activepieces 发布 0.93.0，把 OAuth2 连接能力加入 mcp-client 组件。相关改动支持发现授权信息，用于接入只提供 OAuth2、未直接给出客户端 ID 与密钥的 MCP 服务。该版本也修复多项 Agent 更新操作误改未指定字段的问题。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-09/4.svg" | relative_url }}" alt="mcp-client 的 OAuth2 连接流程。填写 MCP 服务网址 → 弹窗完成 OAuth2 授权 → 发现并调用工具" loading="lazy"></figure>

- 合并说明写明：当其余字段可以被发现时，用户只需手工填写 MCP 服务网址；点击连接后通过弹窗完成授权。可发现性取决于服务提供的信息。
- 作者报告以示例 Aleph MCP 做本地测试，验证 OAuth2 连接、工具发现和调用；这不是对所有 MCP 服务的兼容性保证。
- 0.93.0 新增 Meta 与 NVIDIA 作为 AI 提供方，并更新部分 Claude 与 Groq 操作以适应旧模型退役。
- 发布说明修复 Zoom、Notion、Discord 的 AI 更新操作重置未提及设置，以及 Trello 更新卡片时未填写 Archived 导致归档状态改变的问题。

**为什么值得关注：** 依赖 OAuth2 的远程 MCP 服务多了接入途径；现有工作流升级时，也可重点复查授权流程和只更新指定字段的行为。
