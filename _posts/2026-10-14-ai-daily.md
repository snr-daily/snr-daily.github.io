## 模型发布

### 1. Google 发布 Gemini 4 Argon：API 首发每百万输入 2 美元、输出 10 美元

Google 10 月 13 日发布 Gemini 4 Argon，面向复杂编码、专业工作流和科学任务。开发者可通过 AI Studio 等入口使用付费 API，Gemini 应用则向 AI Ultra 和 Pro 订阅者开放。模型支持 API 输入与输出合计 100 万 token 的统一额度，并提供新的 continuation 协议供长任务接续。首发价格有截止日期，不能当成长期定价。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-14/1.svg" | relative_url }}" alt="Gemini 4 Argon 的可用入口。开发者 API → 个人开发环境 → 应用与搜索" loading="lazy"></figure>

- API 首发价为每百万输入 token 2 美元、输出 10 美元，缓存输入享 95% 折扣；优惠期于 2026 年 11 月 30 日结束，之后常规价为输入 4 美元、输出 20 美元。
- Antigravity 的本轮个人入口面向 Google AI Ultra 订阅者；Gemini 应用与搜索 AI Mode 的入口面向 Ultra 和 Pro，不能把各入口权限混写。
- 官方报告在 ADK Python 的优化中，长会话内存会话准备时间减少 40%，冷导入加快 21%；这是指定工程案例，不是所有代码任务的通用提速。
- 100 万 token 是统一输入输出上限，长输出会占用同一额度；实际使用需按官方开发文档设置接续协议。

**为什么值得关注：** 可以在自己的长任务和代码库上比较完成质量、耗时与总费用。预算应同时计入输出和推理消耗，并按优惠结束后的价格测算长期成本。

来源：[Google DeepMind 发布公告](https://deepmind.google/blog/introducing-gemini-4-argon/)

### 2. Liquid AI 发布 LFM2.5-24B-A2B：24B 总参数、2B 激活，面向端侧 Agent

Liquid AI 10 月 13 日开放 LFM2.5-24B-A2B 及其基础模型权重。新版保留混合架构与稀疏专家设计，改为显式推理模型，上下文从 32K 扩至 131K。官方测试突出工具使用与指令遵循，同时也列出编码和知识任务落后较大模型的结果。2B 指每个 token 的激活参数量，不代表只需存放 2B 权重。

- 模型有 40 层，每个 MoE 块含 64 个专家、每次选择 4 个；总参数 24B，激活参数 2B。
- 官方同组 vLLM 测试中，ToolSandbox 得分 80.71，Qwen3.6-35B-A3B 为 75.02；SWE-Bench Verified（OpenCode）分别为 51.00 和 66.20。
- 官方报告 M5 Max 解码 184 token/s、Ryzen AI Max+ 395 为 114 token/s；单 B300 超过 21K 输出 token/s 是高并发吞吐，不能与端侧单流速度直接比较。
- 首日支持 llama.cpp、MLX、vLLM、SGLang 和 ONNX；模型权重通过 Hugging Face 提供。

**为什么值得关注：** 端侧 Agent 的选型应结合工具成功率、权重内存和推理长度。激活参数较少可以降低单 token 计算量，但不能据此推断所有设备都能流畅运行。

## 开源项目

### 3. LightOn 发布 ColGrep-Agent-2B：代码搜索少用 34.3% API token，但耗时增加

LightOn 10 月 12 日发布本地代码搜索 Agent ColGrep-Agent-2B，为主编码 Agent 查找文件、行号和相关代码。在 Sonnet 5.5 的 Claude Code 代码搜索实验中，每题 API token 从约 142K 降到 93K。与此同时，每题耗时从 13.0 秒增至 21.6 秒，正确率观察值从 83.3% 降至 80.8%。因此，这更适合作为节省云端上下文的具体实验，而不能直接称作全面提速或完整编码任务已验证。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-14/3.svg" | relative_url }}" alt="ColGrep-Agent：每题云端 API token。Grep 基线 142K；ColGrep-Agent 93K" loading="lazy"></figure>

<details class="snr-data"><summary>查看数据</summary><table><thead><tr><th>项目</th><th>千 token，越低越好；仅限代码搜索实验</th></tr></thead><tbody><tr><td>Grep 基线</td><td>142K</td></tr><tr><td>ColGrep-Agent</td><td>93K</td></tr></tbody></table></details>

- 实验包含 13 个仓库、52 个代码搜索问题，每题在四种设置下各运行三次，共 624 次会话。
- Agent 模式 API token 减少 34.3%，95% 置信区间为 28%–40%；统计只含云端输入输出，不含本地 2B 模型 token 和硬件成本。
- 正确率差异的置信区间较宽，统计不显著不等于已经证明无损；Balanced 模式则在观察正确率 83.3% 时减少约 21% token。
- 本地模型通过 ColGrep 多向量语义搜索和只读终端探索仓库，再把代码位置返回主 Agent。

**为什么值得关注：** 可先在大型仓库的定位任务上试用，并同时记录 token、等待时间和漏找情况。降低云端账单与提高交互速度需要分别验收。

### 4. Hugging Face 推出 Llama Windows：托盘下载模型，提供本地兼容 API

Hugging Face 团队成员 10 月 13 日介绍 Llama Windows，把 llama.cpp 包装为 Windows 11 原生托盘应用。用户可以从推荐列表下载量化模型，加载后打开聊天界面，也能让脚本调用同一个本地服务。应用会连接已有 llama.cpp 服务，或管理自己的运行时，降低命令行入门步骤。它是本地推理工具入口，不是新的 Llama 模型发布。

- 应用使用 WinUI 3，支持 Windows on Arm 与 NVIDIA RTX Spark；公告称无需管理员权限或手动编译。
- 默认本地服务位于 localhost:9931，OpenAI 兼容客户端使用 /v1 入口；模型列表可通过 /models 查询。
- 模型保存在标准 Hugging Face 缓存，可与其他工具共享，也可在设置中迁移缓存位置。
- 门控或私有模型需要 Hugging Face 访问 token；推理可在设备上完成，首次下载和必要的鉴权仍需要网络。

**为什么值得关注：** 如果需要给 Windows 应用提供统一的本地模型服务，这类托盘入口可减少启动与模型管理成本。部署前仍应按目标设备检查内存、量化格式和模型许可证。

来源：[Hugging Face 团队发布说明](https://huggingface.co/blog/huggingface/llama-windows)

## 开发工具

### 5. Anthropic 披露 Scion：五个月将内部单体仓库从 Git 迁移到自建系统

Anthropic 10 月 13 日介绍内部版本控制系统 Scion，以及五个月完成单体仓库迁移的过程。公司称日合并量从 5 月约 2,500 次增长到 9 月超过 30,000 次，代码管理、构建和 CI 随之成为瓶颈。Scion 把历史查询、提交与合并等操作放到服务端，客户端按需获取对象并保留有限缓存。它是面向极端规模的内部方案，官方明确不将其定位为通用 Git 替代品。

- Scion 假定客户端始终在线，使用服务端 API 处理差异、历史和合并，不再要求每个客户端拥有完整仓库。
- CI 每天约执行 2,500 万次代码检出；这反映其特殊负载，不能外推到普通团队。
- 作者报告相比原 Git 镜像基础设施，CPU 与内存需求降至约 1/200，CI 获得 25% CPU 容量收益；这些是内部部署结果。
- 系统与 Antique 评审工具、搜索及 CI 深度配套，迁移涉及整个开发生命周期；本次是技术经验披露，未宣布通用公开发行版。

**为什么值得关注：** Agent 产出增多后，检出、合并和验证可能先于写代码达到瓶颈。普通团队可先检查缓存、稀疏检出与服务端查询开销，再判断是否需要改变版本控制架构。

来源：[Anthropic 工程原文](https://www.anthropic.com/engineering/redesigning-source-control)

### 6. GitHub 用 ModernBERT 筛查疑似凭据：提交后扫描中位耗时减少 86%

GitHub 10 月 13 日披露新的上下文凭据分类器，用小型 ModernBERT 替换此前流程中的远程大模型判断。系统先用正则找出疑似字符串，再结合路径、变量名和相邻代码区分真实凭据与示例值。官方报告，相比原 LLM 流程，提交后扫描的中位执行时间减少 86%，服务成本减少超过 98%。效率提升还让通用凭据检测能够用于 push protection，在推送被接受前反馈。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-14/6.svg" | relative_url }}" alt="GitHub 通用凭据检测流程。正则生成候选 → ModernBERT 分类 → 告警或过滤" loading="lazy"></figure>

- 分类器采用 ONNX 导出与 8 位量化；模型负责判断候选，正则仍承担高召回的候选生成。
- 生产客户 A/B 测试中，按仓库所有者加权的告警接受度相对提升 11.5%；它不是准确率提升 11.5 个百分点。
- 同一公开流量上的离线测试报告精确率相对提高 13%、召回率相对提高 19%，与线上接受度属于不同指标。
- 耗时口径为提交后扫描的中位执行时间，成本口径为紧凑分类器对比原远程 LLM 流程；并非整个安全产品的成本降幅。

**为什么值得关注：** 对目标明确、可以标注和评估的任务，小模型分类器可能比持续调用通用生成模型更合适。接入凭据告警后仍需核实、撤销和轮换真实泄漏的密钥。

来源：[GitHub 模型设计与评估](https://github.blog/ai-and-ml/githubs-model-for-secret-detection-finding-more-secrets-with-less-noise/)

### 7. NVIDIA 公开语音微调 skills：空管测试 WER 从 77.00% 降至 22.46%

NVIDIA 10 月 13 日用空中交通管制语音案例说明，如何由 Agent skills 组织领域语音识别微调。Nemotron 3.5 ASR Streaming 0.6B 经分阶段适配后，在两小时人工标注 ATCO2 测试集上的词错误率从 77.00% 降至 22.46%。通用英语 WER 同时从 3.50% 小幅升至 3.63%，说明领域收益仍需与通用能力保持一起检查。这是特定数据和训练方案的案例，不是安装 skill 后自动获得同样效果。

- 编排 skill 定义目标与实验范围，NeMo 专用 skill 负责兼容的训练与评估；安装指令不等于已经装好训练框架或启动训练。

**为什么值得关注：** 领域 ASR 应同时保存数据划分、配置、原始预测和两类测试成绩，尤其检查呼号与数字错误。小规模可信标签可以很有价值，但不能省略测试集隔离。
