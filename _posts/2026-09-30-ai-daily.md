OpenAI DevDay 2026 是本期主线：GPT-6.1 Sol 以 GPT-6 Astra 五分之一的价格逼近其能力，常驻 Agent「dots」开始向 Pro 用户推送，面向开发者的 Sign in with ChatGPT、Decisions API 和 Codex Security Cloud 也同日发布。Anthropic 前沿红队则发文评估智谱 GLM-5.3，认为可自由下载、能端到端写出漏洞利用的模型已经出现。

## 模型发布

### 1. OpenAI 发布 GPT-6.1 Sol：价格是 Astra 的五分之一，编码和电脑操作接近 Astra

OpenAI 9 月 29 日在 DevDay 2026 上发布 GPT-6.1 Sol，这是一周前发布的 GPT-6 Sol 的升级版。OpenAI 称它在 Agent 编码、电脑操作和专业文档工作上接近旗舰 GPT-6 Astra，而标准输入、输出价格只有 Astra 的五分之一。同场还正式推出高速推理档位 Ultrafast，生成速度最高每秒 300 个 token，价格为标准档的 6 倍。据多家媒体报道，OpenAI 前一天刚取消了原定 10 月发布的 GPT-6.1 Astra，原因是安全测试没有通过，GPT-6.1 Sol 因此成为这次大会上唯一的新模型。

- 价格：每百万输入 token 2 美元、输出 10 美元，与 GPT-6 Sol 相同；缓存输入从 0.20 美元降到 0.10 美元。GPT-6 Astra 为输入 10 美元、缓存输入 1 美元、输出 50 美元。API 模型名 gpt-6.1-sol。
- 可用范围：已上线 API，以及面向 Plus、Pro、Business、Enterprise 和 Edu 用户的 ChatGPT Work 与 Codex；据 The Next Web，普通 ChatGPT 对话里暂时还没有。
- OpenAI 自报成绩：在覆盖 47 种工具的业务流程基准 AutomationBench 上，中等推理强度下比 Claude Opus 5.5 高 2.2 个百分点，成本约为其三分之一，比 GPT-6 Sol 高 4.8 个百分点；在 OSWorld 2.0 上与 Astra 相差 2.1 个百分点，单任务成本约为 Astra 的七分之一。
- 行为测试（见系统卡附录）：遇到拒绝访问等明确限制时试图绕过的比例为 23.5%，GPT-6 Sol 为 64.4%，Astra 为 17.4%；OpenAI 说明这些测试多为低风险场景，而且没有启用产品中的全部防护。
- Ultrafast：在 Codex 中最高快 8 倍、API 中最高快 6 倍，API 价格为标准档 6 倍。Astra 版已上线，Sol 版“即将推出”；需要新的每月 500 美元的 Pro 500 或 Enterprise 套餐。

**为什么值得关注：** 对大量跑 Agent 的团队，缓存输入价格减半往往比标称单价更关键，因为长任务会反复读取同一批系统提示和仓库上下文。以上成绩都是 OpenAI 自己测的，切换前最好在自己的任务上对比 Sol 和 Astra 的效果与单任务成本。

## 研究

### 2. Anthropic 评估智谱 GLM-5.3：能端到端写出漏洞利用，防护几乎一绕就过

Anthropic 前沿红队 9 月 29 日发布对智谱（Z.ai）开放权重模型 GLM-5.3 的分析。Anthropic 认为，GLM-5.3 和五个月前只向受信任防御方开放的 Claude Mythos Preview 一样，已经能自主完成从发现漏洞到写出可用利用代码的全过程；不同的是，GLM-5.3 任何人都能下载，发布时也没有有效的防滥用措施。在模拟测试中，用简单手段就能让它在 64% 到 100% 的情况下接受明显恶意的攻击请求，而同样的手段对带防护的 Claude 模型都没有奏效。Anthropic 称其结论与美国 NIST 下属 CAISI 9 月 17 日的评估大体一致，CAISI 认为 GLM-5.3 是迄今网络攻防能力最强的开放权重模型，落后美国前沿约四个月。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-09-30/2.svg" | relative_url }}" alt="GLM-5.3 对明显恶意攻击请求的执行率。直接请求 0%；谎称红队演练 64%；预填思考 token 92%；去除拒绝机制（abliterated） 100%" loading="lazy"></figure>

- 利用能力：在针对 Chrome V8 已知漏洞的 ExploitBench 上，GLM-5.3 在 410 次尝试中 50 次写出端到端利用，Mythos Preview 为 56 次；在内部二进制利用基准的 100 个随机任务中，GLM-5.3 完整劫持控制流的比例为 4%，Mythos Preview 为 6%，而 Claude Opus 4.6 和 GLM-5.2 都是 0。
- 真人配合测试：研究员在沙箱中用 GLM-5.3 测试某主流浏览器的 Linux 版，一天之内、投入很少人力，模型就在 JavaScript 引擎里找到多个未知漏洞，并串成一个访问网页即可读取访问者任意文件的利用，漏洞已报告给维护方。
- 已知漏洞：用较小的 GLM-5.3-Flash，根据公开信息把 Chrome 的 CVE-2026-11645 和另一个已知漏洞串成针对 ARM64 的可靠利用链，绕过了指针认证（PAC）；人工投入约 20 分钟，模型工作 8 小时，按智谱 API 价格约 20.40 美元。
- 绕过防护：直接请求时 GLM-5.3 全部拒绝；谎称自己是红队演练 Agent，有 64% 的情况会执行；预填思考 token 让它“看起来已决定照做”，比例升到 92%；用去除拒绝机制的 abliterated 版本则是 100%。
- 去除拒绝的成本：Anthropic 团队首次尝试花了约 2200 GPU 小时（约 4400 美元），估计熟练团队约需 600 GPU 小时；处理后在 JailbreakBench 和 HarmBench 上拒绝率从 90% 以上降到约 3% 和 2%，GPQA-Diamond 成绩不变。

**为什么值得关注：** 这意味着接近前沿水平的漏洞利用能力已经可以在本地免费获得，维护方从公开补丁到被利用的时间窗口会进一步缩短，打补丁和依赖升级的节奏需要相应加快。这份报告出自有竞争关系的厂商，但方法和数字都公开，可以与 CAISI 的评估对照阅读。

### 3. 通义千问团队公开 QwenGyre：用来训练单次近百万 token 的超长程 Agent

阿里通义千问团队 9 月 27 日在 arXiv 提交论文，介绍在线强化学习框架 QwenGyre，专门用于训练“超长程” Agent，这类任务单次执行可能持续数小时、与环境交互数百次、单条 rollout 接近 100 万 token。论文指出两个难点：各条执行的耗时差异极大，同步训练时 GPU 要等最慢的几条任务，大量闲置；执行过程中频繁分支（例如在工具调用处分叉、上下文压缩后生成摘要分支），产生大量重复轨迹。QwenGyre 用弹性调度器在不中断正在运行的执行的前提下，把 GPU 在 rollout 和训练之间动态调配，再用轨迹处理器重建分支历史、给部分进展打分并去掉重复路径。

- 旗舰规模：论文称 QwenGyre 已用于团队旗舰模型 Qwen 3.8 2.4T 的训练，单条 rollout 约 70 万 token，48 步训练后 NL2RepoBench（从自然语言需求构建完整代码仓库）从 52.5% 提升到 58.5%。
- 效率：在相同 GPU 预算下，端到端速度比“训练和推理共用 GPU 轮流切换”的 Colocate 方案快 1.21 到 1.85 倍，比固定划分 GPU 的 Async 方案快 1.38 到 1.78 倍。
- 实验范围：除 NL2RepoBench 外，还在 DeepSWE 和 TerminalBench 上评估；较小规模实验用 Qwen 3.6 122B，旗舰实验用四个各 48 节点的计算单元。
- 实现：GPU 角色切换时通过 RDMA 迁移缓存，推理参数和 KV 缓存卸载后再恢复训练参数；论文摘要没有提到是否开源代码。

**为什么值得关注：** 这篇论文透露了 Qwen 3.8 旗舰的规模（2.4 万亿参数），也说明头部团队已经在用近百万 token 的单次任务做强化学习。对搭建 Agent 强化学习基础设施的团队，“弹性调度 + 分支去重”是应对长尾耗时的直接思路。

### 4. 论文：每个问题只让教师回答一个无关的词，就能把编程能力“偷”给学生模型

一篇 9 月 24 日提交、本周登上 Hugging Face 每日论文榜首的论文发现，后训练带来的能力会在与任务无关的输出里留下“影子”，并能借此转移给别的模型。作者提出“主动无任务蒸馏”（ATD）：挑选一批与目标任务无关、且教师和学生共同的公开祖先模型在两个普通词之间几乎拿不定主意的提示，让经过私有后训练的教师每次只回答一个词，再用这些“提示加一个词”训练学生。整个过程不需要目标任务的样本、教师的 logits 或参数，但学生仍然学到了教师在目标任务上的能力。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-09-30/4.svg" | relative_url }}" alt="主动无任务蒸馏（ATD）怎样转移能力。共同的公开祖先 → 挑选“两可”提示 → 教师只答一个词 → 学生学习提示-词对 → 能力随之转移" loading="lazy"></figure>

- 主实验：以 Qwen2.5-1.5B-Instruct 为公开祖先和学生起点，教师是在代码数据上做过 DPO 的 LoRA。5664 条单词回答（覆盖 128 个词，经审查不含代码、数学或基准相关内容）训练出的学生，在 HumanEval+ 上达到 51.22%，与教师整体编程水平相当，比严格匹配的对照组高 5.34 个百分点。
- 行为确实被复制：在教师相对祖先新解出的 19 道 HumanEval+ 题上，学生解出 64.47%，对照组为 21.05%；有的题学生采用了教师特有的实现规则，而这些规则从未出现在训练用的词里。
- 挑选提示是关键：同样的教师调用次数下，只用普通提示的被动方案比 ATD 低 4.27 个百分点。
- 泛化：在科学知识、常识推理、阅读理解等 6 个选择题基准上也观察到迁移；换成 Qwen3-1.7B、Qwen3-4B 和 Llama-3.2-1B，平均效果同样为正。
- 局限：实验都在 1.5B 到 4B 的小模型上，提升幅度只有几个百分点。

**为什么值得关注：** 模型提供方通常认为只返回简短、与任务无关的输出就不会泄露能力，这篇论文说明即便是一个词也携带可利用的信号，前提是攻击者掌握同源的公开基座。对发布“开源基座 + 私有微调”模型的团队，这提示防蒸馏需要考虑同源攻击者。

## 开源项目

### 5. NVIDIA 开源表格基础模型 Kumo Tabular：不训练、不调参，一次前向完成分类和回归

NVIDIA 在 Hugging Face 发布表格数据基础模型 Kumo Tabular，可商用。它的用法类似大模型的上下文学习：把一张带标签的表和要预测的行一起输入，模型一次前向计算就给出分类概率或回归预测，不需要训练、调参或特征工程。过去二十年这类任务主要靠梯度提升树，每个新问题都要从头走一遍收集标签、做特征、调参的流程。NVIDIA 称 Kumo Tabular 在 TabArena、BeyondArena、TALENT 和 ScoringBench 四个榜单上都排名第一。

- 规格：三个尺寸，参数量 2800 万到 2.15 亿；分类和回归是两个独立模型；许可证为 OpenMDW-1.1。
- 结构：用列注意力理解每个值在所在列中的含义，用行注意力学习特征之间的交互，最后由一个 Transformer 让待预测行参考带标签的行；注意力温度随行数对数增长，表格变大时注意力不会被“摊薄”。
- 训练数据：完全用人工合成的表格预训练，每张表从随机因果图生成，并刻意加入缺失值、重复行标签冲突、高基数类别等真实数据中的毛病；小、中、大三个版本分别见过约 3500 万、7100 万、1.37 亿张表。
- 成绩：在 TabArena 上以 1950 的 ELO 排名第一；在 BeyondArena 上 ELO 1418，同样第一。
- 局限：只直接处理数值和类别列，文本、图片、时间戳要先用内置流程转成特征；一次前向最多 10 个类别，更多类别由库用纠错输出码扩展。表格远超训练范围或预测行与上下文行分布不同时，准确率可能下降。

**为什么值得关注：** 对手里有大量表格预测任务的数据团队，这类模型可以作为梯度提升树之外的“零训练”基线，先快速看能做到什么水平。NVIDIA 提醒上线前仍要在自己的留出数据上验证准确率和校准。

## 开发工具

### 6. OpenAI 推出常驻 Agent「dots」：每个 Agent 有自己的云端电脑，空闲时也在找事做

DevDay 的主打产品是 dots，这是一类在 ChatGPT 里全天候运行的 Agent。用户给它一个目标，它就持续推进，可以同时处理多个项目，并从反馈中学习用户的偏好。每个 dot 由 GPT-6 Astra 驱动，拥有一台带浏览器、终端和文件存储的云端电脑，用户随时可以打开查看，也可以点“Take over”接管。它和 ChatGPT Work 里的电脑操作功能不同：后者每次由用户发起任务、操作用户自己的屏幕，而 dot 默认在自己的电脑上工作，需要写代码时交给 Codex。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-09-30/6.svg" | relative_url }}" alt="dot 在不同状态下能做什么。空闲时主动研究 → 接到任务 → 按用户规则判断 → 敏感动作先自动审查 → 监控兜底" loading="lazy"></figure>

- 接入：通过插件可以连接 4000 多个应用；用户可以在 ChatGPT 桌面端、网页和手机上发消息或打语音电话，也可以在 Slack 和 Microsoft Teams 里找它，上下文在各渠道之间保持。经用户许可，它也能直接在用户的笔记本上工作。
- 主动研究：没有任务时，dot 会在后台找可以帮忙的事，此时只能用只读工具，不能发消息、改内容或控制浏览器。
- 权限规则：用户可以为具体动作设置允许、需要批准或禁止；涉及账号或对外分享信息的动作要先经过自动审查，改密码这类敏感操作始终留给人。它可以使用已保存的密码而不让模型看到密码本身，监控系统发现安全问题时可以暂停或停止任务。
- 可用范围：9 月 29 日起向 ChatGPT Pro 和 Business Premium 用户推送，部分账户要等几天；欧洲经济区、瑞士和英国的 Pro 用户暂不开放。Enterprise、Edu、Healthcare 客户可在管理员开启后试用测试版。
- 计费：套餐内含一个 dot，和它聊天不计入用量，但它在 Codex 或 ChatGPT Work 里发起的任务照常计算；第一个月额度放宽。更多 dot、更快速度或更大工作量以后另行收费，价格未公布。
- 企业版“专员 dot”：由企业分配独立身份和凭据，负责采购、发票处理等固定岗位，先以试点方式推进；OpenAI 正与微软合作，让它们可以在 Agent 365 中统一管理。

**为什么值得关注：** 常驻、主动、跨渠道的个人 Agent 已经成为 Meta Muse 之后各家的共同方向，dots 的“空闲时只读、敏感动作先审查”是一种值得参考的权限分层。开发者若要被 dot 调用，需要尽早提供插件或 MCP 接入，并考虑 Agent 代用户操作时的审计与撤销。

### 7. DevDay 开发者平台更新：Sign in with ChatGPT、Decisions API、Codex Security Cloud

除了新模型和 dots，OpenAI 在 DevDay 上还发布了一批面向开发者的平台功能，Decrypt 统计全天共 20 多项。其中与开发者关系最直接的有几项：让用户在第三方应用里花自己 ChatGPT 套餐额度的 Sign in with ChatGPT；让最便宜的 Luna 模型从固定选项中快速做判断的 Decisions API；把 Codex 用于持续安全扫描和自动修复的 Codex Security Cloud；以及支持电脑操作的 Agents API。OpenAI 还表示，Codex 的 Agent 框架现在同时驱动 dots，并且是开源的。

- Sign in with ChatGPT：用户登录后，第三方应用可以消耗用户 ChatGPT 套餐的额度，而不是由应用自己为 token 付费，用户可以控制每个应用能用多少。首批列出 16 家合作方，包括 Devin、Notion、Vercel 等；Plus 和 Pro 用户可用。
- Decisions API：把输入（文本或图片）和一组预设选项交给 Luna 模型，快速返回一个选择，用于内容分类、请求路由或决定 Agent 下一步。目前是有限预览，计划几天内扩大开放。
- Codex Security Cloud：可以按需或定时扫描整个 GitHub 仓库、检查每个新提交、去重并在云端准备修复，使用专攻安全的 Daybreak 模型，面向 Pro、Business、Enterprise、Edu 用户。据 Simon Willison 的现场记录，OpenAI 内部安全冲刺中 36% 的发现是重复的，自动补丁经过对抗式核验后回滚率约 1%，配套 CLI 已开源。
- Agents API：新增电脑操作，并把 Codex 的多 Agent、工具搜索和上下文压缩能力开放给开发者，由 OpenAI 托管运行环境；同时与 AWS 推出 Bedrock Managed Agents，可在 AWS 内运行 OpenAI Agent。
- 其他：插件扩展允许第三方在 ChatGPT 里做侧边栏、交互面板和文件查看器；ChatGPT Sites 新增定时任务和插件数据；面向企业的 OpenAI Marketplace 允许用已承诺的采购额度购买合作方软件。

**为什么值得关注：** Sign in with ChatGPT 可能改变 AI 应用的成本结构，开发者可以把模型费用转给已订阅的用户，但也意味着更依赖 OpenAI 的账户体系。Decisions API 说明“快速选择题式调用”已成为独立的产品形态，做分类和路由的团队可以关注它的延迟和定价。
