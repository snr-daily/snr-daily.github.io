Anthropic 公布 Agent 记忆实验：整理笔记和回查原始记录能帮助后续任务，但收益取决于任务。开发工具方面，Google Gen AI Python SDK 3.0 更改默认 API 与 HTTP 客户端，Claude Code 和 Qwen Code 更新后台任务与文件事件。

## 研究

### 1. Anthropic 用离线整理改进 Agent 记忆，强调回查原始记录

Anthropic 于 11 月 6 日介绍 Agent 记忆的分层设计，并报告离线整理记忆的实验。系统可把会话记录整理成笔记和互相链接的知识页，再为后续任务加载索引。作者发现，回查原始记录有助于纠正错误笔记，知识页与搜索结合时也能改善部分任务表现。

- 在约 35 万份内部文档构成的语料上，团队设计了 25 道问题。只用搜索时，达到的评分标准占 53%；使用逐步完善的知识页加搜索，最终达到 61%。
- 同一实验中，只用知识页的最好结果为 48%。该指标是满足评分标准的比例，不是通用问答准确率。
- 部分法律文档任务没有显示清晰收益；另一个任务中，知识页甚至比原始文档更大。维护记忆本身需要计算资源。

**为什么值得关注：** 编者判断：可把搜索作为基础，再评估整理记忆的增益；需要同时计入维护成本，并让重要笔记能追溯到原始记录。

## 开发工具

### 2. Google Gen AI Python SDK 3.0 改用 v1 API 与 httpx2，升级需检查默认配置

Google 发布 Gen AI Python SDK 3.0.0，修改两项默认行为。Gemini Developer API 默认版本由 v1beta 改为 v1，默认 HTTP 客户端由 httpx 改为 httpx2。旧代码如果依赖 beta 模型别名、特定证书来源或 httpx 类型，需要核对配置后再升级。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-08/2.svg" | relative_url }}" alt="SDK 3.0 的两项默认行为变化。Gemini Developer API → 默认 HTTP 后端 → 传输与证书配置" loading="lazy"></figure>

- GitHub 发布于 11 月 6 日，版本说明标记为 11 月 5 日。Vertex AI 与 Enterprise 客户端不受此次 API 默认值修改影响，仍默认使用 v1beta1。
- gemini-flash-latest、gemini-flash-lite-latest 和 gemini-pro-latest 等别名只在 v1beta 可用。可改用具体模型版本，或显式指定 v1beta；代码中的 HttpOptions.api_version 优先于环境变量。
- httpx 不再默认安装。要沿用该后端，需安装 google-genai[httpx]；若希望不修改代码而恢复默认选择，还需设置 GOOGLE_GENAI_HTTP_CLIENT=httpx。
- 未设置 SSL_CERT_FILE 或 SSL_CERT_DIR 时，httpx2 默认使用操作系统证书信任库。自定义 Timeout、Limits、传输层及直接捕获的底层异常，需与实际 HTTP 后端匹配。

**为什么值得关注：** 升级验证应同时覆盖模型名称解析、请求传输、证书与异常处理；仅检查导入成功不足以确认旧集成仍按预期工作。

来源：[Google 官方 3.0.0 发布说明](https://github.com/googleapis/python-genai/releases/tag/v3.0.0)

### 3. Claude Code 2.1.319 将 MCP 长任务转入后台，完成后通知 Claude

Anthropic 发布 Claude Code 2.1.319，在终端加入 MCP tasks 支持。MCP 服务以任务形式返回的工具调用会立即转入后台，完成后再通知 Claude。版本还增加直接拒绝需弹窗批准调用的设置，并修复部分 MCP 连接与续接问题。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-08/3.svg" | relative_url }}" alt="终端中的 MCP 任务处理路径。MCP 返回任务 → 立即转入后台 → 任务结束后通知" loading="lazy"></figure>

- MCP tasks 的后台处理面向终端。设置 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND 后，可恢复在工具调用内等待；不能把这项更新理解为所有工具调用都变成后台任务。
- permissions.denyInsteadOfPrompting 让原本需要权限提示的调用直接被拒绝，当前轮继续执行；该设置覆盖终端、子 Agent 与队友。
- 修复与旧 MCP 服务的连接协商问题，以及恢复长时间运行的 claude.ai 连接器任务时偶尔丢失结果的问题。

**为什么值得关注：** 使用 MCP 长任务的团队可检查完成通知和恢复行为；自动化环境若启用直接拒绝模式，还需确认流程能处理权限拒绝。

来源：[Anthropic 官方 2.1.319 发布说明](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)

### 4. Qwen Code 0.27.0 为本地会话新增文件变更 hook，并修正取消状态

Qwen Code 发布 0.27.0，为本地非托管会话加入 FileChanged hook。集成可以接收新增、修改和删除事件，包括编辑器或外部进程造成的变化。版本还将取消的 shell 任务标为 interrupted，并修复 VS Code 写入提供方配置时影响同级模型设置的问题。

- FileChanged 可监听工作目录中的文件名，也能通过成功的同步 SessionStart 或 FileChanged 输出注册绝对路径文件及递归目录。事件包含所属会话、配置的绝对路径和 add、change 或 unlink。
- 递归发现默认排除隐式符号链接、.git 与 node_modules 子树，除非显式注册。明确注册的符号链接可观察目标变化，通知中保留配置的别名。
- 该 hook 限于本地非托管会话，不覆盖 managed、remote 或 sandbox 会话。初始状态对齐与持久同步仍由集成负责，不能只靠事件通知获得完整同步保证。
- 取消的 shell 任务不再误标为 completed；发布说明同时列出 VS Code 提供方配置保留同级模型设置的修复。

**为什么值得关注：** 记忆或索引集成获得了接收外部文件变化的入口。实际接入时仍需自行处理首次扫描、事件遗漏后的校对和持久化。

来源：[Qwen 官方 0.27.0 发布说明](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.0) · [FileChanged 合并说明与适用范围](https://github.com/QwenLM/qwen-code/pull/13969)
