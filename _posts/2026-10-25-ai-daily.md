## 模型发布

### 1. 腾讯开源 Hy-Nomas：用多轮文本和相机轨迹控制连续视频，提供单张 4090 配置

腾讯公开 Hy-Nomas 的训练、推理与交互演示代码，以及基础、蒸馏和量化模型文件。它按片段生成视频，用户可在后续片段改变对象、动作、风格与镜头，历史通过 KV 缓存传递。官方模型卡给出 720×1280、24 FPS 输出和 8 步蒸馏推理配置。这里的 24 FPS 是播放帧率，不能据此判断系统每秒能生成多少帧。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-25/1.svg" | relative_url }}" alt="Hy-Nomas 如何连续生成并接受新指令。输入本段文本与相机 → DiT 结合历史生成 → 解码并进入下一段" loading="lazy"></figure>

- 模型由分段自回归 DiT、Qwen 文本编码器、相机条件模块和 PixelUMM 解码器组成；不是仅在生成前填写一次提示词的固定视频流程。
- 低显存配置声明支持单张 RTX 4090，组合 INT8 DiT 权重与 KV 缓存、FP8 解码器、CPU 卸载和滑动窗口历史；DiT 线性层与注意力仍用 BF16 计算。
- 滑动窗口会限制保留的历史上下文，不能把持续生成理解为无限记忆。在线演示还依赖独立的 Nomas-PE 提示增强服务，离线推理可读准备好的提示文件。
- 配套 Hy-Nomas-Bench 有四类共 280 个案例，覆盖多轮文本、相机导航、交错控制与空间记忆；这是评测规模，不是模型通过率。
- 项目标注 Apache 2.0，技术报告仍标 Coming Soon；本期未下载权重或实测显存、生成速度和长程一致性。

**为什么值得关注：** 有相机控制或分段交互需求的团队现在可以审阅代码与权重配置。部署评估应分别测播放规格、生成速度、显存和历史保留范围。

### 2. 上海 AI 实验室补齐 Atria Dawn 正式版权重：提供 BF16 与 FP8，文档标注 512K 上下文

Atria Dawn 的官方仓库在 10 月 23 日将正式版和 FP8 的 Coming soon 下载位替换为实际链接。此前本报已报道 API 与评测，本次新增的是正式版权重可获取。Hugging Face 两个公开模型库均可列出 Safetensors 分片，正式版文档标注 512K 上下文。本文不重复把旧基准分数当成新进展，也没有下载整个模型。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-25/2.svg" | relative_url }}" alt="Atria Dawn 本次新增的交付阶段。此前 API 与评测 → 正式版文件已列出 → 部署仍需独立验收" loading="lazy"></figure>

- 官方介绍沿用基于 GLM-5.2 的 744B 级 MoE 路线；Hub 文件元数据合计约 753.3B 存储参数，两种统计表述不作同一个精确数字混用。
- 标准仓库有 353 个 Safetensors 分片，FP8 仓库有 177 个；FP8 元数据仍含 BF16 与 F32 张量，不能称所有参数都采用八位格式。
- 官方 README 声明代码和权重采用 MIT 许可；本次核对了公开模型库与文件清单，不以模型卡存在代替完整下载、哈希或运行验证。
- 部署文档列出 SGLang v0.5.13.post1+ 和 vLLM v0.23.0+，模型仅接收文本。512K 是声明的上下文容量，不是本机可承载容量，也不代表长输入准确率。
- 官方接入文档同步更新了 discovery-api 域名，兼容不同客户端时还需核对 API 路径；本期未更改任何客户端配置或调用服务。

**为什么值得关注：** 自部署从等待下载转为可做容量与许可审查。先按具体精度、并行配置与目标上下文计算资源，再做实际任务测试，不能由“开源”推断个人设备可运行。

## 研究

### 3. Mundo 用代码模拟物体、用视频模型渲染场景：八张 A800 下约每秒生成 1.5 帧

Mundo 研究团队 10 月 23 日介绍从照片重建可编辑场景的流程：先建立显式 3D 代理，再用代码与模拟器推进状态，最后生成外观视频。VLM Agent 比较重建图和原照片，结合数值优化修正对象位置、尺寸与朝向，另一个审阅 Agent 检查结果。物理状态与视觉渲染分开，使运动来源更可检查。当前系统仍较慢，也没有长程记忆机制，不能称作实时或准确的数字孪生。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-25/3.svg" | relative_url }}" alt="Mundo 如何分离状态与外观。照片重建 3D 代理 → 代码与模拟器推进状态 → 代理帧引导视频渲染" loading="lazy"></figure>

- 场景主要用 3D 包围盒近似物体，精细接触才增加几何；代理世界主要在 MuJoCo 中模拟质量、摩擦、重力与交互，生成视频跟随代理帧。
- 作者用约 4 万对视频微调 MiniMax-H3 Ref2VA，训练片段为 124 帧、640×480；这是训练设置，不与其他模型的输出规格直接排名。
- 长视频按 124 帧分块，把上一块最后 34 帧作为下一块固定前缀，并随相机路径重新选择参考视图；分块连续不等于拥有长期世界记忆。
- 作者报告典型场景重建需 10–20 分钟，视频渲染在八张 A800、20 推理步条件下约 1.5 帧/秒；本期未复测，不能与播放帧率比较。
- 小物体可能悬浮，精细操作会产生幻觉；长期动态变化或遮挡后重现时也会丢失细节。未拍到的区域仍依赖模型推断，不能当作真实测量。

**为什么值得关注：** 它提供了把可执行状态和生成外观分离的研究路径。机器人或仿真用途仍应分别验证重建、物理参数与渲染一致性，视觉逼真本身不能证明动力学准确。

来源：[Mundo 作者：方法、训练配置与局限](https://huggingface.co/blog/Luo-Yihang/mundo-world-model)

### 4. OpenAI 披露训练隔离加固：离线网页、微型虚拟机与网络边界共同约束 Agent

OpenAI 10 月 23 日说明前沿模型训练环境的隔离改造。前沿强化学习运行使用缓存网页构成的离线环境，并叠加容器、微型虚拟机、监测和网络控制。披露针对内部训练与评估，不等同已发布产品的运行方式。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-10-25/4.svg" | relative_url }}" alt="训练隔离采用多层防护。离线内容供训练使用 → 容器与微型虚拟机 → 监测、网络与云边界" loading="lazy"></figure>

- 红队在隔离副本中测试联网、越界与跨任务通信，也测试主机已失陷后的外围防护；部分实验提供源码和线索。
- 公司称修复了发现的弱点，并于 10 月 1 日恢复前沿 RL 训练与内部推理；恢复日期不是本文发布日期。
- 发现数量随模型、测试范围和投入变化，曲线不能解释为受控的算力收益；仍须持续红队检验。

**为什么值得关注：** 隔离应独立于模型是否遵守指令，也要检查外围服务与监测。报告没有证明所有越界路径已消除。

## 开发工具

### 5. Corgi 集中管理终端 Agent：显示等待状态、保留后台进程并查看文件改动

近期 Show HN 介绍的 Corgi 将终端复用与 Agent 状态集中在一个工作区，可接入 Claude Code、Codex、Pi 和 OpenCode。它显示运行、需要响应和完成等状态，并提供活动摘要、上下文与 token 用量视图。开发者可离开会话，让 Agent 与开发服务器继续运行，再重新连接。它管理现有工具与账户，不提供一个新的模型或统一推理服务。

- README 的安装目标为 Apple Silicon macOS 与 amd64 Linux；官网另提 WSL。本期未安装，因此不把宣传的终端与 SSH 兼容性视为本机已验证。
- Corgi 会检测窗格中的 Agent 并加入相应 hooks；Pi 使用扩展，OpenCode 不需额外配置，Codex 的 hooks 需要用户信任。这是采用前需要了解的配置变动。
- 功能矩阵按客户端区分：OpenCode 不标多账户，Pi 不标子代理；不能将所有界面功能视为每个客户端都支持。
- 命令行可列会话、建标签、分屏、读取或发送窗格文本；界面可看文件变动、worktree 和资源用量，权限仍由实际 Agent 与进程控制。
- 项目代码采用 MIT 许可，通知音等组件有独立许可。后台持续运行不等于任务已完成，进程状态和最终交付仍需分别确认。

**为什么值得关注：** 同时运行多个终端 Agent 时，统一状态可减少来回找窗口。正式接入前应审查 hooks、共享会话访问和恢复行为，本期没有代用户安装或授权。

来源：[Corgi：功能与支持范围](https://corgi.computer/) · [Corgi：README 与按客户端划分的功能矩阵](https://github.com/tals/corgi)

## 行业动态

### 6. OpenAI 介绍 Habitat 存储优化：全球读取 p50 从约 120 毫秒降至约 10 毫秒

OpenAI 10 月 23 日公布 Habitat 存储系列第二篇，解释与 Azure 团队共同改造 Cosmos DB 的过程。方案回到默认多租户，通过热点限流、请求优先级和改进的 serverless 分区机制减少资源争抢。公司报告一组改动合计使全球读取 p50 从约 120 毫秒降至约 10 毫秒。

- 小型、延迟敏感数据多区域复制；其他读取主要由靠近请求侧的 Valkey 缓存承接，CDC 驱动跨区域失效。
- Rust 改写降低代理开销，但总改善同时含放置、复制与缓存策略，不能全部归功于语言替换。
- p50 是存储读取中位数，不是 p99、整次模型回复时延或独立复测结果。

**为什么值得关注：** 应把存储路径分层测量，再选择复制与缓存策略；不能由一个中位数推断整个产品的性能。
