月之暗面开放 Kimi K3.1 Pro 权重，OpenAI 推出 Images 2.6。另有面向文档字段抽取的小模型、硬件原型设计案例和 Datasette 的并排聊天面板。

## 模型发布

### 1. 月之暗面开放 Kimi K3.1 Pro 权重，支持百万 token 上下文

Kimi K3.1 Pro 是在 Kimi K3 基础上后训练的多模态 Agent 模型，可处理文本和图像。官方模型卡列出 2.8 万亿总参数和 1040 亿激活参数，上下文长度为 1048576 token。相对 K3，模型把原来的全注意力层换成门控稀疏注意力层。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-05/1.svg" | relative_url }}" alt="Kimi K3.1 Pro 的模型规格。接收文本和图像 → 通过混合注意力层 → 由专家路由分配计算" loading="lazy"></figure>

- 模型为 93 层混合专家架构，注意力层由 69 层 KDA 和 24 层 Gated DSA 组成。
- 每 token 选取 16 个专家，模型卡另列 2 个共享专家。
- 官方发布规格为 MXFP4 权重和 MXFP8 激活，采用量化感知训练。

**为什么值得关注：** 选型时应分别核算常驻权重和推理开销。1040 亿激活参数描述参与计算的规模，部署容量还要考虑完整权重和缓存。

来源：[月之暗面官方模型卡](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)

### 2. OpenAI 推出 Images 2.6，API 提供 Flare 与 Sunburst

OpenAI 公布 Images 2.6，并宣布在 ChatGPT、Codex 和 API 提供。新版加入 GIF 创作，API 支持图像标记和 SVG 导出。API 有侧重速度的 Flare 和侧重细节与编辑一致性的 Sunburst。

- 官方称整体生成速度较此前快 50%。Flare 在低画质下最快约 6 秒。
- Sunburst 在中高画质设置下提供更精细的输出和更好的编辑一致性。
- API 的 complexity 控制规划复杂度，quality 控制视觉细节和保真度。

**为什么值得关注：** 做批量改图时，可以按场景复杂度和画质分别评估耗时，用实际工作负载测量吞吐。

来源：[OpenAI Images 2.6 发布公告](https://openai.com/index/introducing-images-2-6/)

### 3. Dharma AI 发布 2B 文档抽取模型，按指定结构输出 JSON

Dharma Field Extractor 从文档图像中提取字段，可自动识别键值，也可按调用方提供的 schema 填充。模型基于 2B 的 DharmaOCR-LITE v1.1，并用 43384 个样本训练 LoRA。在作者的 1638 个评测用例中，模型综合分为 0.834。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-05/3.svg" | relative_url }}" alt="文档字段抽取综合分。Dharma Field Extractor 0.834；Claude Opus 5 0.816；GPT-5.6 Luna 0.741" loading="lazy"></figure>

<details class="snr-data"><summary>查看数据</summary><table><thead><tr><th>项目</th><th>数值</th></tr></thead><tbody><tr><td>Dharma Field Extractor</td><td>0.834</td></tr><tr><td>Claude Opus 5</td><td>0.816</td></tr><tr><td>GPT-5.6 Luna</td><td>0.741</td></tr></tbody></table></details>

- 评测含 546 份文档，覆盖无 schema、仅指定真实字段及混入不存在字段三种情形。
- 综合分结合字段路径匹配 F1、匹配值的编辑距离相似度和有效 JSON 比例。
- 同一对照中的 Claude Opus 5 为 0.816，GPT-5.6 Luna 为 0.741。作者使用低推理档位的 API 配置。
- 自托管成本按单张 L40S 的 GPU 时间估算。API 成本则按用量与价目计算，两者采用不同计费口径。

**为什么值得关注：** 对固定表单，可以先用真实样本测字段缺失、表格行序和类型错误，再评估不同部署方式的成本。

来源：[Dharma AI 作者发布与评测](https://huggingface.co/blog/Dharma-AI/dharma-field-extractor)

## 研究

### 4. OpenAI 用 Astra 协助设计硬件原型，制造前仍需多轮审查

OpenAI 公布一款可与 Codex 对话的实验设备。两名团队成员用 Astra 在不到一周内完成设计工作，代工厂随后在不到一个月内制造出一小批原型。项目覆盖外壳、电路板和软件，准备投产时仍需多轮审查和迭代。

<figure class="snr-figure"><img src="{{ "/assets/figures/2026-11-05/4.svg" | relative_url }}" alt="实验设备从设计到样机。设计设备 → 审查制造约束 → 代工制造样机" loading="lazy"></figure>

- Astra 参与外壳和内部支撑结构设计。
- 模型还参与元器件选择、PCB 布局与连接，以及固件和软件集成。
- 官方报告的制造问题包括生产限制、尺寸公差和装配细节。

**为什么值得关注：** 原型项目可把模型产出纳入制造审查，并把公差、装配和供应商约束写入验收标准。

来源：[OpenAI 硬件工程案例](https://openai.com/index/accelerating-engineering-for-the-physical-world/)

## 开发工具

### 5. Datasette Agent 0.5a0 新增并排聊天面板

Simon Willison 发布 Datasette Agent 0.5a0 预发布版。聊天面板可以与表格或查询页面并排显示。与 datasette-apps 配合时，用户可以创建数据库应用，并在应用旁边继续通过聊天修改。

- 面板支持保持在 Datasette 内容页旁边。
- 数据库应用创建和修改流程依赖 datasette-apps。
- 作者提供在线体验入口，可使用 GitHub 账号登录。

**为什么值得关注：** 把对话和查询结果放在同一个界面，便于一边修改，一边检查数据或应用的变化。

来源：[Simon Willison 发布说明](https://simonwillison.net/2026/Nov/3/datasette-agent/)
